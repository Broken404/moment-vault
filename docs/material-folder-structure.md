# 素材文件夹结构

更新日期：2026-10-20。状态：用户已确认一条素材一个文件夹，支持多图、多视频及图片与视频混合归组，媒体与 Markdown 描述从草稿阶段一起保存，通过插件内的轻量勾选列表批量审核，入库时整个文件夹一起移动。采集时自动命名，之后可在审核列表改名，同名自动补编号；正式产品尚未实现此流程。

稳定 ID、描述字段与文件操作的统一约定见 [首版产品与技术方案](formal-plan.md)。

## 已确认的组织规则

每条素材使用独立文件夹，内含一个或多个实际媒体文件和一份描述。一次批量拖入的图片统一构成一条素材，已有多个单个素材也可合并为一条。草稿箱与资产库采用相同结构，人工审核通过时将整个条目文件夹移到资产库，保持全部媒体和描述在一起。

以下为结构示意，条目文件夹自动命名，内部媒体的扩展名与实际格式一致：

```text
草稿箱/
└── 20261020-图片组-001/
    ├── 图片-001.png
    ├── 图片-002.jpg
    └── 描述.md
```

新增录制的视频条目保存经成片处理的 MP4（H.264、AAC），已有视频导入保留原文件与实际格式，截图保存原图。视频成片处理仍待正式实现与验收，现有 WebM 试验文件保持原有格式与证据。文件夹不代替媒体本体，也不改变先草稿、后人工审核的规则。

这样用户使用本地文件工具时，能在同一位置查看素材和相关说明；复制、备份或审核入库时也可以一起处理。

## 已确认的命名与改名方式

采集时自动生成素材名称，不要求用户先起名或确认名称。有可靠来源时采用“收集日期＋来源平台＋来源标题”，例如 `20261020-YouTube-原视频标题`；没有可靠标题时采用素材类型与编号，例如 `20261020-图片-001`。来源未知时不编造平台或标题。

用户之后可在审核列表中手动修改素材名称，并同步修改对应条目文件夹的名称，方便在本地目录中辨认。改名不改变原媒体、收集时间或来源记录；文件夹内的媒体与描述保持关联。

自动保存、手动改名或审核入库遇到同名文件夹时，自动补充编号，保留已有条目，不覆盖已有内容。同一来源可采集多条素材，不因为标题或链接相同就合并。

多图素材没有统一可靠标题时采用“日期＋图片组＋编号”命名，之后同样可在审核列表改名，不要求为批量保存先填写名称。

图片与视频混合归组、或多个视频归组后，没有统一可靠标题时采用“日期＋素材组＋编号”，例如 `20261020-素材组-001`，同样支持后续改名。

## 已确认的批量保存与合并

一次批量拖入多张图片时，在同一素材文件夹中分别保存原图，共用一份 `描述.md`；这是一条素材，不按图片张数统计条目。单张采集仍可形成单条素材，用户可在草稿整理阶段选中多条，合并成一条后再审核入库。

合并采用归组方式，支持多张图片、多个视频及图片与视频混合，各个媒体文件分别保留。描述保留各成员已有的来源、收集时间、视频区间和备注，再提供整条素材的共同备注；不将不同来源改写成同一个来源，也不以合并时间替代原收集时间。

例如，一条混合素材可以包含 `图片-001.png`、`视频-001.mp4`、`视频-002.mp4` 和共同的 `描述.md`。合并不重编码、拼接或改变各个媒体文件的内容。

合并完成后，原草稿条目由合并后的单条素材替代；全部媒体与说明完整保存后才清理原条目，失败时保留原数据并如实反馈。素材文件夹内出现同名媒体时补编号，保持描述中的文件对应关系。

## 已确认的描述内容

用户已确认先采用以下内容，后续再扩展：

- 可确认的来源：可靠的链接或用户确认的来源说明；未知时留空。
- 收集时间：实际导入或录制的时间。
- 自由备注：用户的收藏理由、想法或其他补充，可随后填写。

采集时不强制填写收藏理由或备注，素材仍按已确认的方式直接保存草稿。无需 AI 才能生成或补充这些内容。

描述文件采用 Markdown，可直接阅读并用普通文本编辑器修改。审核列表中的每条素材提供“编辑说明”，用户可补充或修正来源、填写备注，点击“保存”后更新对应的 `描述.md`。来源与备注可留空，不影响入库；编辑不会改变原媒体或收集时间。

描述中的排版与字段顺序由正式技术方案统一规定。视频的来源区间与实际录制区间建议一并保留，不能把它们混为同一个时间。

外部截图的来源仍需用户提供或确认，不能把当前网页直接写成真实来源；导入时间不冒充截图发生时间。尚未填写的个人理解可以留空，不为填满描述而自动编造。

## 对保存与审核的影响

- 从草稿阶段一起保存媒体与描述，不在审核通过后才临时创建结构。
- 审核以完整素材条目为单位，媒体与描述一起移入资产库；目标完整写入后才清理源条目。
- 一条素材内的多个媒体和描述文件不能在结果统计中被分别算成多条素材。失败时保留源数据并如实反馈，不显示整条入库成功。
- 批量审核采用插件内的轻量勾选列表，显示缩略图、名称和收集时间，可用本地软件打开素材查看；勾选多条并点击“入库”后，统一移动选中条目的完整文件夹。具体规则见 [本地素材查看与审核入库](local-material-access.md)。
- 文件夹采用自动命名、后续可手动改名的方式；重名时自动补编号，采集时不增加必须先填写名称的步骤。
- 草稿移入回收区和恢复时，同样以完整素材文件夹为单位处理，媒体与描述一起保留。回收内容不列入待审核列表；恢复后回到所属草稿箱，不直接入库，第一版不自动清空回收区。

本轮确认的是正式产品规则，没有执行素材文件操作。测试目录中的整夹转移验证见 [技术验证记录](technical-spike-results.md)，不能替代正式安装与任意配置目录下的验收。
