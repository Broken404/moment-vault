# 素材文件夹结构讨论

更新日期：2026-10-19。状态：描述先包含可确认的来源、收集时间和自由备注已确认；一条素材一个文件夹的组织方式继续细化，描述格式、命名与批量选择方式尚未确定，未实现文件操作。

## 当前建议

用户提出“一条素材一个文件夹，一个是素材，一个是描述”。建议草稿阶段就采用同一结构，人工审核通过时将整个条目文件夹移到资产库，保持媒体和描述在一起。

以下仅为结构示意，文件夹和文件名不是已确定的规范：

```text
草稿箱/
└── 20261019-001/
    ├── 素材.png
    └── 描述.md
```

视频条目对应保存实际录到的视频文件，扩展名与实际媒体格式一致；截图保存原图。文件夹不代替媒体本体，也不改变先草稿、后人工审核的规则。

这样用户使用本地文件工具时，能在同一位置查看素材和相关说明；复制、备份或审核入库时也可以一起处理。

## 已确认的描述内容

用户已确认先采用以下内容，后续再扩展：

- 可确认的来源：可靠的链接或用户确认的来源说明；未知时留空。
- 收集时间：实际导入或录制的时间。
- 自由备注：用户的收藏理由、想法或其他补充，可随后填写。

采集时不强制填写收藏理由或备注，素材仍按已确认的方式直接保存草稿。无需 AI 才能生成或补充这些内容。

描述文件建议使用能够直接阅读和编辑的格式，例如 Markdown，具体格式仍待细化。视频的来源区间与实际录制区间建议一并保留，不能把它们混为同一个时间。

外部截图的来源仍需用户提供或确认，不能把当前网页直接写成真实来源；导入时间不冒充截图发生时间。尚未填写的个人理解可以留空，不为填满描述而自动编造。

## 对保存与审核的影响

- 建议从草稿阶段一起保存媒体与描述，不在审核通过后才临时创建结构。
- 审核以完整素材条目为单位，建议媒体与描述一起移入资产库；目标完整写入后才清理源条目。
- 一条素材的两个文件不能在结果统计中被算成两条素材。失败时保留源数据并如实反馈，不显示整条入库成功。
- 此前确认从草稿箱多选文件；改成独立子目录后，批量选取方式还需讨论并验证，不默认系统选择器已经支持多选目录或跨目录多选。
- 文件夹自动命名、重命名和目标重名策略仍待细化；采集时不增加必须先填写名称的步骤。

当前只记录候选方案，没有创建素材目录或移动用户文件。
