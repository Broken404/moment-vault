# 视觉与交互设计记录

日期：2026-10-20。状态：“灵感画板”、P3-C、四宫格、深浅色、位置与显示规则、主要页面，以及功能动作、菜单过渡和状态反馈已确认；第三十九轮整体定稿并启动实施。历史各轮的待定状态仅描述当时，不代表当前仍未批准。

最新收图决定：用户已取消全部吃图片动画，并确认当前小爱心预览效果；此前关于嘴型、张合、吞入与咀嚼的预览仅作为弃用历史，不再进入正式方案。

功能和技术草案见 [首版产品与技术方案](formal-plan.md)。用户明确指出艺术设计、艺术表现和交互细节尚未敲定，继续一次讨论一个问题，以可见预览帮助判断。技术可实现不等于设计已确定，文档中此前给出的尺寸、位置、配色和动画参数均为暂定建议。

## 已确认的设计约束

- 普通网页内悬浮入口，展开屏幕录制、设置、接收截图、素材管理四个功能。用户希望入口更像可爱的桌宠，四个功能比首轮预览更聚拢；原扇形动画与布局随新造型继续调整，不能原样照搬首轮分散的圆弧排列。
- 图片接收后自动保存至草稿箱，一次批量拖入统一为一条素材；保存中、成功和失败须准确区分。
- 视频选段要求在原播放器进度条上拖动 A/B 并高亮选区，列为三站目标页面的首版验收要求；用户明确备用仅在迫不得已时使用。保留独立预览窗用于边界画面和整段试播，并强调缓存与卡顿。已确认录制开始后收起选段界面，使用视频画面外的小状态条；录制与预览分别表达。
- 草稿审核采用轻量勾选列表，支持本地查看、改名、编辑说明、归组与入库。
- 搜索、标签、分类、后续资产使用和 AI 不在本轮设计范围。

## 当前比较方向

- 克制工具：紧凑面板、明确分隔、单色图标，强调低打扰与快速操作。
- 灵感画板：温暖纸感、画面优先、松弛留白，强调保存内容时的创作感。
- 精密工作台：结构化分区、蓝色焦点、状态条，强调后续视频选段与整理的一致性。

用户已选择“灵感画板”，并指出首轮预览的四个功能过于分散，希望悬浮图标像可爱的桌宠，以增加吸引力。其余方向不作为主方向。

## 桌宠与菜单：当前决策

已确认：保留灵感画板界面方向；网页悬浮入口具有可爱桌宠的角色感；用户所说的桌宠不代表真正的宠物或动物形象，以 Claude、Grok Bot 那类简洁角色为参考；角色保持原创，具体造型继续确定；四个功能集中在角色附近，减少视觉分散。

已确认：点击 P3-C 后，在它身边展开四宫格紧凑菜单，四个入口按两行排列，菜单风格与像素角色一致；深浅色效果采用当前通过的预览。展开的具体动画参数与角色动作仍需设计。

用户比较像素与圆润几何版本后选择 P 系列的像素效果，并在 P3 调整版中选择 P3-C；现已通过四宫格布局与深浅色效果。表情动作细节继续确定；拖动与点击区分、大小与不透明度及显示规则已在后续轮次确认，不预设养成、对话或复杂宠物系统。

角色概念图仅用于本轮讨论，尚未成为正式产品资产；候选名称只是区分造型的临时称呼，正式命名未讨论。

首轮曾制作立体纸感角色对比图：A 奶油色团子，B 杏桃色口袋精灵，C 折纸页精灵。用户明确全部不喜欢，改为日漫风格；三者均未入选，此前对 B 的推荐不再作为当前建议。

此前根据日漫偏好制作了二维角色概念，但把画风偏好错误地延伸为萌兽与精灵形象。用户已纠正，日漫偏好不能作为继续画动物、兽人或复杂角色插画的依据。界面的灵感画板方向继续保留，桌宠无需沿用界面的纸张材质。

第二轮二维日漫角色对比图中的 A 奶油杏色小灵兽、B 浅黄色漂浮精灵、C 紫色调皮小妖怪也已全部被用户否定，不再保留为候选。菜单布局和角色动作未在这些概念图中验收。

## 最新造型约束

用户明确：桌宠是一种入口的角色感，可以参考 Claude 或 Grok Bot 的形象；不要真正宠物、福瑞或此前两轮的造型。

据此提出的方向：简单且有辨识度的抽象轮廓，少量五官，通过眨眼、视线和轻微形变表达性格。用户看过两种画法后选择 P 系列像素效果，圆润几何不作为当前主方向；不再以复杂动物角色设定图代替简洁软件角色设计。

生成图用于确定角色方向，不直接作为已经可以交付的像素源文件。

## 第五轮：P3-C 与同风格紧凑菜单

已制作可交互预览，角色按 P3-C 的阶梯式圆团轮廓重绘。两个菜单候选共用深灰、米白与黄色点缀、阶梯切角和方形按钮；仅比较布局：

- 四宫格：上排为屏幕录制、接收截图，下排为素材管理、设置，采集入口靠前；两行集中排列，作为当前推荐。
- 四行列表：相同功能顺序，图标和文字横向排列，整体较窄但更高。

菜单在角色上方近距离展开，尾部与角色相接。预览支持点击角色展开/收起、关闭按钮、Escape 收起、按钮选中反馈和一次短促的角色响应；按钮只演示样式，不实际录制或操作素材。角色尺寸暂用 64 px，提供 48/64/80 px 与间距调节供视觉比较，尚未视为最终默认值。

用户已确认的是角色方向和菜单须同风格的要求；四宫格/列表、排序、配色细节、图标、菜单动画和角色反馈都仍在本轮预览评审中。整体灵感画板方向保留，未因菜单采用像素风而将所有页面改为像素游戏界面。

## 第六轮：跟随系统的深浅色外观

用户要求同步桌面系统的深色、浅色模式，保证清楚可见。已补入方案：默认跟随 Windows 应用颜色模式，同时提供固定浅色/深色；用户固定模式后优先使用其选择，返回跟随系统时立即同步当前状态。设置与正式验收细节见 [设置界面](settings.md)。

已更新同一份桌宠菜单预览，顶部可切换“跟随系统 / 浅色 / 深色”，四宫格和列表共用主题。浅色为暖白底与深字，深色为深灰底与米白字；角色保留 P3-C 深灰、米白、黄色配色，通过像素描边适应不同背景。手动切换两套配色已在本地预览检查，系统变化监听已写入预览；尚未进行 Windows 系统设置切换与正式扩展/本地助手集成验收。

本轮没有把新增主题要求视为对菜单布局、具体色值、描边粗细或动画的整体确认；仍以四宫格作为当前预览起点，保留列表对比。主题切换不改变角色形状和四个入口职责。

## 第七轮：安静陪伴与功能状态（收图动作已由第十二轮替代）

用户已选择“安静陪伴”，明确不用向鼠标靠近；每个功能中的桌宠状态应不同，例如喂图片时做吃的动作。

已确认的方向：平时以偶尔眨眼为主，固定在用户摆放的位置，不主动向鼠标移动、靠近或追随。功能操作触发相应角色反馈，而不是全天持续做动作；P3-C 的抽象像素造型和四宫格入口继续保留。

以下表格按最新决定更新；视频选段、素材管理和设置的动作方向在第三十六轮确认，具体节奏与联动效果通过预览继续评审：

## 第八轮：吃图片动作预览

已制作独立可交互预览，保留 P3-C 与已通过的深浅色配色，用“张口 → 图片缩小进入嘴中 → 咀嚼 → 满足表情 → 安静待机”的连续动作表现投喂。单次约 2.5 秒，角色只做轻微形变，不朝鼠标移动。时长、嘴部和咀嚼幅度仍待用户看过后确认。

预览提供示例图片、播放按钮、直接拖放目标与本地图片选择，支持多图成组和连续输入的演示队列；实际图片只在当前预览中显示，不上传或写入草稿箱，界面明确注明仅演示。已检查按钮播放、吞入状态和满足表情的衔接；文件拖入与正式 Edge 保存链路仍需在实现阶段验收，不将预览等同于真实采集交付。

正式产品仍在图片交入后立即发起保存，动作与写入并行；成功表情须等实际保存完成，失败保留图片及重试入口。批量投喂仍统一生成一条素材，不能因演示动作而逐张拆分。

## 第九轮：调整投喂嘴型与动作

用户否定首版吃图片动作，认为不够可爱，并特别指出不喜欢嘴型。首版宽大的黑色槽口、反复张合的咀嚼及其动作参数不作为正式实现依据；P3-C 造型、四宫格菜单和明暗效果继续沿用已确认结果。

本轮预览改为“小幅期待 → 图片缩成小片 → 短暂小口吸入 → 闭嘴鼓腮两下 → 眯眼满足 → 安静待机”。去掉黑色大嘴和反复开合：入口瞬间使用约角色宽度八分之一的米白像素小圆口，咀嚼时为短小的闭口线，结束为小笑嘴；待机仍无嘴。用轻微的身体形变、短暂暖黄脸颊和眼睛变化承担主要表情，角色不朝鼠标靠近。

预览下方提供入口、闭嘴和满足的三张表情定格，方便观察短暂嘴型；这是评审辅助，不是正式产品需要常驻的界面。已检查修订后的定格外观、按钮触发、图片靠近和播放结束恢复待机。

用户随后否定了把可爱简化为小口的设计判断，并明确要求吃豆人式效果；本轮小圆口、闭口线、小笑嘴及鼓腮不再作为后续方案。预览只显示本地图片，不上传或写入素材目录；实际保存成功、失败的产品规则不变。
