# Codex 与 Claude 参考资料方向

更新日期：2026-10-20。状态：已明确素材主要供 Codex、Claude 参考；本轮只确定本地文件兼容方向，未构建或验证 AI 接入。

范围补充：用户明确资产搜索、检索和使用后续自行设计，本篇相关内容保留为未来研究候选，不作为本轮首版功能或当前验收要求。

## 当前参考资料的使用目标

用户明确保存的视频主要用于喂给 AI 做参考，常用工具为 Codex、Claude。当前产品输出独立的本地媒体文件和 Markdown 说明，后续工作流使用同一份素材，不为特定模型建立专用资产库。视频成片选用 MP4（H.264、AAC），图片保留原图。

本轮官方文档确认了 Codex 的图片输入方式，见 [Codex CLI 文档](https://learn.chatgpt.com/docs/codex/cli)；Claude Code 支持通过图片路径、拖放等方式使用图片，并可读取 Markdown 目录，见 [Claude Code 常见工作流](https://code.claude.com/docs/en/common-workflows)。Claude 普通聊天的文件入口另列文档与图片类型，见 [Claude 文件上传说明](https://support.claude.com/en/articles/8241126-upload-files-to-claude)。用户尚未区分具体 Claude 客户端，不能将这些入口混为同一能力。

据此采用普通文件作为资料基础，但不将保存 MP4 等同于已验证模型原生理解完整视频。视频抽帧、音频处理与实际模型使用留待 AI 阶段确认；当前不自动抽帧、转写、生成理解说明或上传到模型服务。

## 已核实的能力

OpenAI 的官方文档将插件描述为可组合 skills、MCP servers 等能力的可复用包；MCP 负责连接工具与数据，skill 负责指导工作流程。见 [插件概览](https://learn.chatgpt.com/docs/plugins) 与 [Skills](https://developers.openai.com/plugins/concepts/skills)。

Codex 的 MCP 文档支持本地进程形式的 STDIO server，以及 Streamable HTTP server。这个能力为未来访问本地资产提供了可研究的入口，但不等于浏览器扩展中的 IndexedDB 会自动对本地进程开放。见 [MCP 官方文档](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)。用户后来已确定素材保存到分别选择的本地目录，后续接入需以实际文件与必要元数据为依据，而非默认读取扩展内部数据库。

## 本项目的建议分工

以下是设计建议，不是官方预设的产品结构：

- Edge 扩展：用户主动采集、来源识别、录制、草稿与正式资产管理。
- Codex：在用户选择的范围内辅助整理，以及按任务检索、理解和使用资产。
- 统一的数据格式：使浏览器侧和后续 Codex 入口能理解同样的来源、附件、用户理解和入库状态。

第一版将媒体与描述保存在用户选择的本地目录，整夹复制即可备份，不另建专用 AI 导出或检索工具。后续资料读取、检索及双向编辑方式由用户另行设计，当前不提前确定接入流程。

不假设 Codex 能直接读取扩展的 IndexedDB；不把文件导出当作已经实时同步；不为接入插件而提前要求用户运行公网服务。

## 可以验证的后续使用场景

1. “帮我整理这批草稿，给出标签和可能的用途。”——生成建议，保持草稿状态。
2. “从我的正式资产里，找几个能表达时间流逝的例子。”——返回实际存在的资产、原始附件和来源。
3. “为这次创意讨论找一些跨领域参考。”——不限制资产主题，解释每条参考与任务的关系。

上述为未来验收场景，当前尚未实现这些工具。

## 接入时必须解决的事项

- 所选运行环境是否能访问本地目录及相应媒体文件。
- 导出的版本和实时库是否一致，更新后如何识别旧副本。
- 用户允许模型读取哪些草稿、正式资产和媒体。
- 外部模型处理媒体前，明确数据流向和使用范围。
- AI 建议与人工确认的写入权限保持区别，AI 不自动完成正式入库。
- 平台原文、截图识别结果及标签作为资料处理，不能借此触发额外操作。

本轮未安装、配置或修改用户的 Codex 插件和 MCP 设置。
