# 自用版本交付前回归

更新日期：2026-10-24。实施依据为已批准的 [正式方案](formal-plan.md)，当前状态见 [实施记录](implementation-status.md)。本页只安排剩余实施与验收，不将已有自动检查、隔离浏览器检查和正式扩展确认混为同一种通过。

## 推进顺序

1. **补齐素材恢复的正式扩展路径。** 附件已经收齐的「继续保存」和多语言刷新保留均已获用户确认。本次补测附件尚未收齐时，能否只重新选择缺失的原文件，沿用同一任务保存为一条完整素材，并保留说明和原文件。
2. **检查连续使用与性能。** 在独立自制素材中检查较多条目、较大附件、连续操作和退出后的资源释放；视频按正式方案补充长视频、竖屏、快速拖动和缓冲场景，记录实际画面响应与内存。出现卡顿或文件问题时先修正再复核。已经通过的基础操作不逐条要求用户重做；新的性能样本也不能替代原有实录证据。
3. **制作并验证自用安装包。** 沿用已批准的 Windows 当前用户安装、Inno Setup 和 .NET 自包含助手，交付扩展构建目录与安装说明。检查首次安装连接、升级保留目录和素材、重启可用及卸载保留素材。商店上架、公开发布和 AI 使用不进入本轮。

## 当前首项：补选原文件恢复

正式扩展沿用已经加载的构建，无需重新加载或录制。真实注册清单及扩展 origin 通信检查已再次通过。通过当前助手在已配置草稿目录中准备一条明确命名的自制任务「恢复验收-补选原文件」：2 个附件，视频已收齐，PNG 仅收到首个 192 KiB 分块。关闭并重新启动准备进程后仍可读出原任务，已收到的分块与目录配置保持不变；没有提交为正式草稿，没有改写既有素材。

下一步在正式素材管理页刷新草稿箱，从「未完成的保存 / Incomplete saves」对该任务点击「选择原文件继续 / Reselect originals」，只补选所列的「待补传原图.png」。预期只出现一条包含原视频和图片的草稿，原待恢复任务消失。

完成后以只读协议和文件检查核对：任务及附件 ID、顺序、名称、来源、备注和创建时间保持一致；两份文件大小、原文件哈希与实际解码通过；无重复条目、无上传记录混入素材，目录配置不变。确认只补传原图的浏览器动作与上述独立检查后，才将该项标记为正式通过。
