# 大量素材首次加载优化

更新日期：2026-10-24。状态：修正已通过实际助手规模测量，正式扩展重新连接另行确认；完整视频性能矩阵与安装交付仍未完成。

## 问题与定位

原来的列表会逐个读取所有素材的 `描述.md`，完成排序和重复标识检查后再返回 40 条。在 500 条新建自制素材中，两次首次请求（含助手启动）分别为 11,555.514、11,995.201 ms；减少到 40 条时通过 2 秒本机诊断。100 条测得 2,048.337 ms，靠近门槛，因此后续使用 500 条作稳定复现，不以该边界样本判断成败。

把启动拆开后，`config.get` 用了 140.020 ms，随后首次列表仍为 10,095.706 ms。临时分段探针在另一份 500 条库中测得扫描总计 9,568.961 ms，其中文件读取 9,366.874 ms、路径检查 112.467 ms、解析 70.233 ms、哈希和文件夹名 6.818 ms。主要等待发生在串行打开并读取新说明文件，不能归结为启动、JSON 解析或图片解码。没有独立证明操作系统缓存、杀毒软件或磁盘驱动内部各自的贡献。

探针只在隔离诊断构建中运行。正式代码的临时输出已移除，诊断构建及生成材料归档在忽略的 `.local-data/first-list-probes`，没有注册该探针助手。

## 修正方式与选择理由

沿用 .NET 自带的异步文件读取和有上限的并行遍历，最多同时读取 16 份说明，减少逐个等待。没有新增数据库、依赖、持久索引、文件监听器或协议字段。

同步和异步读取共用同一份路径检查与解析代码；所有说明仍实际读取、校验和计算版本。每份结果放回原目录顺序对应的位置，全部结束后再集中生成警告、检查整库重复 ID、按创建时间稳定排序和分页。损坏或暂时被占用的单份说明保留原文件并产生警告，其余素材继续显示。写入和转移仍执行完整定位检查。

每次重新列举都读取当前文件，因此外部编辑、同长度且保留修改时间的编辑、新增、移除、目录改名和切换素材目录仍可发现。读取函数在返回前关闭说明文件，不长期保存媒体字节或打开的文件句柄。

先测了 8 份并发：500 条降至 1,410.813 ms，1,500 条仍为 3,984.666 ms。16 份的一次 1,500 条测量为 2,330.292 ms，32 份为 2,120.815 ms，增加并发收益不明显，最终保留 16 份。以上 1,500 条试验在沿用 500 条的严格 2 秒门槛时均报失败，保留原始记录，不改写为通过。

## 最终构建测量

使用相同脚本、新建的自制素材库及真实长度前缀协议，测量时没有并行执行其他项目检查。原版本为上一轮大图读取修正版；两者都保留完整素材检查。首次耗时包含助手进程启动，未清空操作系统磁盘缓存，不是物理冷盘、正式浏览器绘制或通用响应时间保证。

| 样本 | 原助手 | 最终修正版 |
| --- | ---: | ---: |
| 500 条，首次列表专项复现 | 11,555.514 / 11,995.201 ms | 1,327.878 ms |
| 1,500 条，首次列表专项复现 | 33,693.256 ms | 2,424.766 ms |
| 100 / 500 / 1,500 条完整规模轮，首次列表 | 上轮分别约 2.06 / 7.76 / 20.48 秒 | 386.742 / 657.800 / 1,747.611 ms |
| 1,500 条完整规模轮，后续列表中位 | 上轮 718.530 ms | 318.455 ms |
| 1,501 条中读回 4,334,289 字节 PNG | 上轮 809.188 ms | 399.315 ms，23 块哈希一致 |

专项诊断保留 500 条的 2 秒门槛，并在原版本上先验证 1,500 条的 3 秒门槛确实失败，再用最终构建通过同一检查。门槛是本机回归诊断，不是产品在所有机器上的承诺；两种规模参数必须与结果一起记录。完整规模轮另行覆盖图片、视频封面、较老条目和已缓存缩略图，主进程工作集采样约 70.7～83.5 MiB；这不是内存峰值，也不含浏览器或 FFmpeg 子进程。

## 验证与使用

新增原生检查覆盖较大列表的完整重复标识检查、坏说明和文件占用警告、等时间稳定排序、分页无漏项和文件不变，以及刷新发现外部同时间戳编辑、新增、移除、改名和根目录切换。实际协议与录制文件管线检查分别记录在结构化证据中。

当前候选助手位于 `dist/host-library-load`；只更换配套本地助手，扩展脚本和目录设置保持原值。正式扩展需重新加载一次以断开旧助手、连接新版本，不需要重新录制或重做上传恢复。用户的实际页面反馈单独记录，不用助手计时替代页面验收。

```powershell
$env:MOMENT_VAULT_TEST_HOST = (Resolve-Path 'dist/host-library-load/MomentVault.Host.exe').Path
node tools/measure-material-library.mjs --check-first-list
node tools/measure-material-library.mjs --check-first-list --items=1500 --max-first-list-ms=3000
node tools/measure-material-library.mjs
```

`--prime-startup` 仅用于拆分启动的诊断，会在计时列表前先执行 `config.get`；结果中的 `firstListIncludesHelperStartup` 为 false，不能作为含启动的首次打开时间。日常规模检查不传此参数。

以往的小库检查没有锁定大量新说明的首次扫描；现在保留独立的首次加载检查，避免只测已预热的列表。原失败、并发对照和最终结果见 [结构化证据](evidence/large-library-startup-2026-10-24.json)。较老缩略图仍可能回退整库定位；视频完整性能和安装包继续按 [交付前回归](release-readiness.md) 推进。
