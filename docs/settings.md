## 用户已明确的设置

入口：悬浮球展开扇形菜单 → 点击“设置” → 显示设置界面。设置界面的具体尺寸与布局后续细化，本轮先明确配置项目。

| 设置项 | 当前要求 | 默认值或状态 |
| --- | --- | --- |
| 草稿箱本地目录 | 单独选择本地文件夹，保存待审核素材的实际文件 | 由用户选择，不擅自决定磁盘路径 |
| 资产库本地目录 | 与草稿箱分开选择，保存审核后的资产 | 由用户选择，不强制共用总目录 |
| 界面语言 | 可以切换插件界面语言 | 建议默认跟随浏览器，首批提供简体中文和 English；此默认与支持列表仍属建议 |
| 方向键调整步长 | 调整当前选中端点，左右对称，单位为秒 | 默认 5 秒，可修改 |
| Ctrl + 方向键调整步长 | 细调当前选中端点，左右对称，单位为秒 | 默认 1 秒，可修改 |
| 快捷键管理 | 查看、调整入口唤出等操作的快捷键 | 具体组合与冲突处理后续细化 |
| 悬浮球外观 | 大小、透明度、恢复默认位置 | 具体默认值后续细化 |
| 恢复默认设置 | 恢复操作配置，保留素材和本地目录选择 | 不删除素材，不清空或更换目录 |

这里的“步长”是每次按键改变的视频时间，不是改变键盘长按时的按键重复频率。长按继续按重复事件累计调整；步长应为有效正数，非法输入有提示。建议提供恢复这两个步长默认值的操作。

用户已经在两种目录方案中明确选择“草稿箱和资产库分别选择目录”，不采用首次强制选择一个总目录再自动建立两个子目录的方案。

## 本地目录的交互建议

- 每个目录设置项显示选择结果及访问状态，并提供“选择文件夹 / 更改”操作。使用系统目录选择器取得相应访问权限，不将一段路径文字当作已经可写。
- 选择或更改目录后检查实际可用性；不可访问、权限失效等状态应可理解，支持重新选择或授权。
- 初次尚未配置可写草稿箱时，保存前引导配置；不能显示“已存入草稿箱”却只留在浏览器临时缓存。
- 有效目录可复用，不应每次接收图片或结束录制都要求重新选择。能否跨浏览器重启持续使用，以及何时需要重新授权，必须实测。
- 本地原图、视频文件与必要元数据的保存目标，以用户选择的目录为准。浏览器内部存储可用于设置、索引、句柄与必要临时数据，不能代替已经承诺的目录保存。
- 更换目录是切换库、仅变更新文件保存位置，还是迁移旧素材，尚待单独讨论；本轮不默认搬迁、覆盖或删除已有文件。
- 草稿与正式资产仍按审核状态区分，配置了资产库目录不代表采集时可以直接进入资产库。

## 技术依据与待验证问题

`showDirectoryPicker()` 可由用户操作触发目录选择器，返回目录句柄，并可请求读写模式；调用受来源与用户激活等条件约束。见 [MDN showDirectoryPicker](https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker)。Chrome 的官方文档示例展示了将目录句柄保存到 IndexedDB 及检查/请求访问权限的方式。见 [File System Access](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)。

这支持优先验证目录句柄方案，不能据此声称网页内悬浮设置、扩展自身来源、跨站页面和浏览器重启后都已经可用。需要验证由扩展自己的来源持有目录访问能力，并让各网页的收集入口通过受控消息使用它；不能把目录权限分散授予每个被访问的网站。

悬浮设置面板如何发起文件夹选择、是否需要一次扩展自身页面完成授权，以及完整原生路径能否显示，都仍需原型核实。只取得目录句柄时应如实展示可获得的信息，不能伪造完整路径。也不擅自引入必须安装的桌面助手。

下载接口的 `filename` 主要是相对于下载目录的路径，不能用任意绝对路径替代本地目录授权。见 [Downloads API](https://developer.chrome.com/docs/extensions/reference/api/downloads)。若目录句柄路线无法满足实际需求，应明确报告缺口，不能静默退回下载目录而声称已保存到用户指定位置。

实现前至少验证：两个目录分别可选与可写；图片和真实视频文件写入正确目录；跨站收集共用配置；重启后的权限与恢复；取消目录选择不破坏旧配置；目录不可用时反馈与重试正确。当前未创建或更改用户的任何本地素材目录。
