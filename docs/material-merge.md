# 草稿合并

2026-10-23 实现。依据正式方案 4.3，合并将多条草稿归组为一条，图片和视频均保留原文件，不重新编码、拼接或自动入库。

## 使用方式

在草稿列表勾选 2–200 条，点击“合并为一条”。附件按当前列表中的条目顺序排列，各条内部顺序保持不变，与勾选先后无关。同名附件补编号，文件名与描述对应更新，附件 ID、来源、收集时间、备注、视频区间和扩展字段保持原值。

合并后的素材自动命名，可在右侧改名。原整组备注按原条目名称分项保留在共同说明中，原完整元数据与备注同时保存在 `描述.md` 的 `mergedFrom` 中；再次合并时保留之前的来源链。右侧有未保存修改时，先保存修改再合并。

页面显示真实完成结果，成功后刷新并选中合并条目。合并尚未确认或原条目清理未完成时，提供“继续合并”；刷新、关闭再打开管理页后保留本目录下的重试信息，不自动重新提交。

## 文件提交与重试

`MergeStore.cs` 负责单一的归组事务，复用现有描述读写、哈希校验及文件路径检查。先检查当前草稿及说明版本，在私有暂存区复制并逐附件核对，重新检查来源未变，再持久化记录并将完整目标一次性发布到草稿列表。目标未完成时不删除来源。

新目标确认完整后清理原条目。来源只读、被占用或发生变化时保留未清理部分，明确报告“合并副本已保存，原条目清理尚未完成”。同一次操作使用固定 ID，助手重启后依据记录恢复；目标已存在时不新建第二份。只允许当前草稿箱直接子目录参与清理，拒绝越界或不一致的记录。小型操作记录留在草稿目录 `.moment-vault/merges/`，用来识别成功回复丢失后的重放。

未登记的额外文件或子目录、缺失或被修改的附件、重复附件 ID，会在发布前拒绝合并并保留原条目；不会静默删除额外内容。说明过大时提示减少选择，避免目标已完成却无法通过 Native Messaging 返回结果。失败暂存仅留在私有管理区，不作为普通素材显示。

扩展在发送前持久化目录、操作 ID、按显示顺序排列的素材 ID 与说明版本。只有已明确拒绝发布或合并完全完成时清除重试信息；通信结果不明、目标有变化或清理未完成时继续保留。普通网页不能调用合并接口，入口沿用既有管理页权限检查。

- 22 项原生文件/协议检查，其中新增 7 项覆盖混合附件、嵌套合并、身份/区间/备注/扩展字段保留、同名文件、外部修改、额外文件、资产库拒绝、重启与部分清理、损坏目标保护、发布中断、越界记录及协议重放。
- `tools/check-merge.mjs` 连接实际自包含助手，以独立临时草稿箱和自制 PNG/MP4 验证两条合并为一条、三个附件不变、MP4 完整解码和助手重启后的重放。没有读取或合并用户现有素材。
