# 上传中断后的恢复

2026-10-23 实现。这里的上传是浏览器将用户选择的文件交给本机助手，沿用正式方案中的本地草稿流程。

## 使用方式

草稿箱上方显示「未完成的保存」，重新打开或刷新管理页、切回窗口、点击刷新均可重新读取本地记录。每条显示原素材名称、附件数、已收齐数量和已收到的字节数；列表每次显示 20 条，可继续加载。

- 附件已经全部收到：点击「继续保存」，直接完成校验和草稿发布，无需重新选择文件。
- 附件尚未收齐：点击「选择原文件继续」，仅列出仍缺的原文件。选择这些文件后继续同一个任务，已收齐的附件保留。取消文件选择或点击「暂不处理」保留任务。
- 不再需要：点击「删除未完成保存」，确认一次「删除后不可恢复」后清理这次暂存。原始文件保留，已保存的素材不能由该入口删除。

网页图片接收失败时保留本页重试，同时提供「查看未完成保存」进入草稿箱；管理页导入失败后会重新读取恢复记录。只有最终完整保存成功才提示「已继续保存到草稿箱」。已收到的内容仍保留时，错误提示不会把它当作正式草稿。

未收到的内容需要原文件补齐。原文件已经丢失时，需要重新收集；旧版任务缺少原文件名等信息时，以原内部附件名提示选择对应文件。

## 实现

沿用草稿目录下 `.moment-vault/pending/<id>` 中的记录、附件和 192 KiB 分块。任务直接由本机磁盘发现，恢复入口不依赖已经关闭页面的内存，也不增加浏览器端整份视频缓存或新的依赖。

新保存记录携带原文件名、字节数及修改时间。重选时先匹配这些信息和媒体类型，允许调整文件选择顺序，但上传及最终附件仍按原顺序保存。随后重放已收到的前缀，由助手逐块比较实际字节；相同分块直接复用原磁盘文件，不同则停止并保留暂存，再接收剩余内容。这会再次传送前缀用于本机核对，不是完全跳过前缀读取。未收到的尾部没有原内容可供独立比较。

分块先写唯一临时文件并刷盘，再原子发布为 `.part`，避免中途写入的文件成为已确认分块。附件组装、完成记录写入、最终哈希与发布沿用原流程；完成记录写入失败后，原始分块仍能在重启后重放。初始保存重试会读取助手返回的完成状态，避免完成确认丢失后再向已关闭的附件追加。最终回复丢失时返回当前草稿中同 ID 的已完成素材。

`uploads.list`、`uploads.get` 和 `uploads.discard` 只允许管理页调用。恢复及新保存各请求携带开始时的草稿目录；与当前配置不一致时拒绝操作，返回原目录后才能继续。损坏的恢复记录显示提示，保留数据，其余可读任务仍可列出；录制继续使用独立的「重试保存 MP4」入口。

删除暂存时最后删除恢复记录；有占用或只读分块时，保留记录供释放后重试。内容清理完成后保留一个仅含删除状态的 ID 标记，阻止旧网页的迟到重试重新创建已删除任务。该标记随所属草稿目录保存，切换目录不搬迁旧数据。

- 新助手的当前用户注册和实际 origin 协议 ping 通过，目录配置哈希未变。正式录制文件管线另通过，产出可解码 H.264/AAC MP4；录制 offscreen 文件哈希不变，无需重复已通过的人工录制。
