# 本地素材查看与审核入库

更新日期：2026-10-20。状态：已确认通过插件内的轻量勾选列表批量审核，入库时移动完整素材文件夹。测试目录中的打开与整夹转移已验证，正式产品的审核列表、目录配置与文件系统集成尚未完成。

本篇记录具体产品规则，实施统一入口为 [首版产品与技术方案](formal-plan.md)。

## 当前产品决定

素材管理负责打开设置中配置的草稿箱和资产库，并提供“审核入库”操作。审核入库使用插件内的轻量勾选列表，展示缩略图、名称和收集时间；图片和视频的完整查看使用本地文件工具，人工审核通过后由插件移动完整素材文件夹。

本轮不提供关键词搜索、标签分类或面向后续资产使用的检索与调用界面，这些由用户后续另行设计；已确认的审核、本地目录查看与删除保留。

入口是已确认的四宫格菜单中的“素材管理”。点击后在独立的浏览器标签页打开，默认显示草稿列表，提供本地草稿箱与资产库目录打开、整理和审核入库操作；草稿回收区从素材管理内访问。“审核入库”和“回收区”均不另增为桌宠四宫格菜单入口。

已确认该管理标签页同时承载完整设置，左侧增加“设置”入口。点击桌宠中的“素材管理”直接进入草稿箱，点击“设置”直接进入设置；已有管理页时复用并切换到对应功能，不反复新建标签页。设置内部布局另行评审，原有素材列表与说明编辑规则继续适用。

页面布局与风格已通过预览：左侧切换草稿箱、资产库和回收区，中间是轻量勾选列表，右侧查看当前条目并编辑草稿说明；批量操作集中在列表上方。列表点击查看与勾选分开，草稿编辑点击“保存修改”后提交；多附件分别保留来源及附件备注，整组备注单列。资产库的说明只读。整体延续暖纸色、深灰、黄色强调与轻像素切角，并适应深浅色及窄窗口；正式文件操作尚未实现。

系统文件夹打开的目标体验是使用文件管理器，例如 Windows 资源管理器。配置的是哪个目录，就打开哪个目录，不擅自改为浏览器默认下载目录。

目录更换采用切换当前库的规则，旧素材保留原地。审核列表只读取当前草稿箱，入库目标为当前资产库；需要使用旧库时可在设置中切换回来，不自动迁移或合并旧素材。切换规则见 [设置界面](settings.md)。

## 打开时的反馈建议

- 目录尚未配置：提示选择相应本地目录，并可前往设置。
- 请求打开目录：实际发送打开请求，失败时说明原因并允许重试；不能只显示“已打开”却没有执行。
- 目录被移动、删除或暂时不可访问：保留原配置，提示重新选择或检查目录，不自动创建替代库。
- 两个“打开目录”操作只用于查看，不触发审核或文件移动；“审核入库”使用单独、明确的用户操作。

## 已确认的批量审核方式

审核入库采用插件内的轻量勾选列表，按素材条目展示当前草稿箱的内容，每条显示缩略图、名称和收集时间。用户可用本地软件打开素材查看，勾选多条后点击“入库”，统一移动选中素材的完整文件夹。这一决定替代此前使用系统文件选择器多选文件的交互。

操作规则：点击“素材管理” → 显示当前草稿箱的素材勾选列表 → 按需用本地软件查看 → 勾选认可的素材 → 点击“入库” → 插件将选中条目的整个文件夹移入已配置的资产库并反馈结果。

素材采集时自动命名，审核列表提供手动改名操作，并同步修改对应素材文件夹名称。保存、改名或入库遇到同名时自动补编号，具体规则见 [素材文件夹结构](material-folder-structure.md)。

一次批量拖入的多张图片显示为一条素材，可显示首张缩略图与图片数量。草稿审核列表提供“合并为一条”，支持多图、多视频及图片与视频混合归组，合并后全部媒体和各自已有来源、收集时间、视频区间及备注保留。

混合素材显示可用的附件缩略图及图片、视频数量。需要完整查看多个附件时打开对应素材文件夹，单文件素材可直接用本地默认软件打开，继续沿用本地查看方式。

点击“入库”表达用户对勾选素材的审核决定；浏览目录、打开素材或仅勾选本身均不触发移动。建议在入口处明确提示“选中的素材文件夹将从草稿箱移至资产库”，不再增加一次重复确认弹窗。

移动规则与反馈建议：

- 执行前检查两个目录已经配置且可访问，未配置时提示前往设置，并验证所选条目来自当前草稿箱。只处理本次明确选中的素材文件夹，用户取消选择时不移动任何文件。
- 入库必须移动整个素材文件夹，包含实际媒体和描述，保持来源、备注等信息与媒体的关联，不能只改变数据库状态或留下失效的文件引用。
- 确认目标文件完整写入后再清理草稿箱中的源文件；写入失败时保留源文件，不能先删源文件再尝试复制。
- 草稿箱与资产库可能位于不同磁盘，跨目录移动、异常中断和重试均需验证。操作未完成时不能显示“已移入资产库”。
- 目标存在同名素材文件夹时自动补编号，保留原有条目，不覆盖文件。
- 批量移动按素材条目反馈结果。部分成功时显示成功与失败数量，保留失败条目及原因；重试只处理未完成项目，避免重复入库。

| 状态 | 建议反馈 |
| --- | --- |
| 移动中 | “正在移入资产库…”及实际处理进度 |
| 全部成功 | “已将 N 条素材移入资产库” |
| 部分成功 | “N 条已移入，M 条未完成”，列出未完成条目并提供重试 |
| 未能完成 | 明确原因并允许重试，保留尚未完成转移的文件；目标已写入但源文件未清理时如实说明 |

审核由用户决定，AI 接入继续后置。当前只记录产品行为，没有实际移动用户文件。

## 已确认的说明编辑入口

审核列表中的每条素材提供“编辑说明”，可补充或修正来源、填写自由备注。点击“保存”后，将内容写入该素材文件夹中的 `描述.md`；文件实际写入成功后才反馈已保存，失败时保留本次输入并允许重试。

来源与备注均可留空，不阻塞入库。编辑来源和备注不改变原媒体或系统记录的收集时间，也不重新自动生成素材名称。用户仍可通过普通文本编辑器修改本地描述文件；插件后续读取本地最新内容，检测到编辑期间文件已被外部修改时，不静默覆盖。

一条素材包含多张图片时，说明同时保留整条素材的自由备注和各图片已有的来源、收集时间与备注，不能将统一编辑的来源静默覆盖到全部图片。具体字段排版由实施方统一设计。

## 已确认的草稿回收与恢复

未勾选或暂时没有决定的素材继续留在草稿箱，不因关闭审核列表而被丢弃。明确不要的草稿可通过审核列表中的“移到回收区”操作，将整个素材文件夹移入应用内的本地回收区，并从待审核列表中移除。

回收区提供恢复操作，将媒体与描述一起恢复到所属草稿箱，恢复后仍为草稿，需再次由用户确认才能入库。恢复遇到同名时自动补编号，不覆盖现有素材；移动与恢复失败时保留原数据并反馈实际结果。

回收区随所属草稿箱保留，切换草稿箱目录不会搬迁旧回收内容，切回旧草稿箱后仍可访问。第一版不自动清空回收区，不设到期自动删除；用户主动永久删除其中素材时，提示“删除后不可恢复”，确认一次后执行。

## 已确认的正式资产处理范围

已入库素材不提供撤回草稿箱或撤销入库操作。用户删除时，提示“删除后不可恢复”，确认一次后直接永久删除整个素材文件夹，媒体与描述一起处理，不经过回收区，不提供删除恢复。用户取消则不执行；执行失败如实反馈，不显示删除成功。

删除按这一简单规则实施，不再增加多层确认、延迟删除或额外恢复流程。草稿原已确认的“移到回收区”操作保留，与正式资产的永久删除分开。

## 素材文件夹与批量选择

已确认每条素材使用单独文件夹，包含实际媒体和 Markdown 描述；草稿箱与资产库保持相同结构，审核入库时整个文件夹一起转移。素材自动命名、后续可改名；描述先包含可确认的来源、收集时间和自由备注，来源和备注可在审核列表中编辑，详见 [素材文件夹结构](material-folder-structure.md)。

勾选列表集中展示分散在各个子文件夹中的素材，选择以素材条目为单位，不要求用户逐个进入子文件夹挑选媒体。关闭列表或取消选择不移动任何素材；完整写入后清理源数据、失败可恢复的原则继续适用，结果数量按素材条目统计，不把媒体和描述分别算两条。

## 官方能力与实现边界

Chrome Downloads 文档提供 `downloads.show(downloadId)`，作用是在文件管理器中显示一项已下载文件；`showDefaultFolder()` 打开的是默认下载目录。二者均不等于接受任意目录路径并打开。由目录句柄直接写出的文件也不能假定已有对应下载记录。见 [Downloads API](https://developer.chrome.com/docs/extensions/reference/api/downloads)。

Edge 官方支持 Native Messaging，使扩展与已安装的本地程序通信。本地程序需要单独分发与注册，浏览器不会因为装了扩展就自动装好它。见 [Edge Native Messaging](https://learn.microsoft.com/en-us/microsoft-edge/extensions/developer-guide/native-messaging)。

正式方案已选择 C#/.NET 本地助手，通过 Native Messaging 连接扩展，负责目录选择、系统打开、读写、合并和整夹入库；安装包与稳定通信仍需实现。临时本地服务的验证结果不等同于正式宿主已安装。

正式实现需核实：自选目录能否真实打开、空目录能否打开、跨磁盘路径与中文空格路径是否正常、扩展重启后是否可用，以及是否额外依赖本地程序。审核入库还需验证当前草稿箱条目的枚举、缩略图与名称对应、调用本地软件查看、批量勾选、来源校验、完整转移和失败恢复。`file://` 在浏览器中打开目录与打开系统资源管理器属于不同体验，不能混称为同一能力。

当前只记录需求与能力边界，没有安装本地程序、修改注册表或实际打开用户素材目录。
