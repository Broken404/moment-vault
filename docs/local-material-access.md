# 本地素材查看

更新日期：2026-10-19。状态：查看方向已明确，系统文件夹打开方式尚未实现或实测。

## 当前产品决定

用户要求素材查看直接跳转到本地文件。素材管理因此以打开设置中分别配置的草稿箱与资产库目录为职责，图片和视频使用本地文件工具查看，当前不制作插件内的完整媒体浏览界面。

入口仍是扇形菜单中的一个“素材管理”。建议点击后提供“打开草稿箱”和“打开资产库”两个操作，草稿箱排在前面；具体选择面板样式后续细化。此前默认先看草稿箱的目标保留为优先入口，素材内容交给本地文件查看。

系统文件夹打开的目标体验是使用文件管理器，例如 Windows 资源管理器。配置的是哪个目录，就打开哪个目录，不擅自改为浏览器默认下载目录。

## 打开时的反馈建议

- 目录尚未配置：提示选择相应本地目录，并可前往设置。
- 请求打开目录：实际发送打开请求，失败时说明原因并允许重试；不能只显示“已打开”却没有执行。
- 目录被移动、删除或暂时不可访问：保留原配置，提示重新选择或检查目录，不自动创建替代库。
- 此入口只用于查看，不自动审核、不移动或删除素材。

当前人工审核如何完成仍待确认：在本地手动挑选与移动，或在插件提供明确审核动作。浏览目录本身不等于审核通过。

## 官方能力与实现边界

Chrome Downloads 文档提供 `downloads.show(downloadId)`，作用是在文件管理器中显示一项已下载文件；`showDefaultFolder()` 打开的是默认下载目录。二者均不等于接受任意目录路径并打开。由目录句柄直接写出的文件也不能假定已有对应下载记录。见 [Downloads API](https://developer.chrome.com/docs/extensions/reference/api/downloads)。

Edge 官方支持 Native Messaging，使扩展与已安装的本地程序通信。本地程序需要单独分发与注册，浏览器不会因为装了扩展就自动装好它。见 [Edge Native Messaging](https://learn.microsoft.com/en-us/microsoft-edge/extensions/developer-guide/native-messaging)。

基于这些接口范围的工程判断：要稳定打开用户任意选择的草稿箱和资产库目录，可能需要轻量本地辅助程序。是否必须采用此方案，以及安装负担，仍需技术验证和产品取舍；本轮不自动增加此安装要求。

实现前必须核实：自选目录能否真实打开、空目录能否打开、跨磁盘路径与中文空格路径是否正常、扩展重启后是否可用，以及是否额外依赖本地程序。`file://` 在浏览器中打开目录与打开系统资源管理器属于不同体验，不能混称为同一能力。

当前只记录需求与能力边界，没有安装本地程序、修改注册表或实际打开用户素材目录。
