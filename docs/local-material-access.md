# 本地素材查看与审核入库

更新日期：2026-10-19。状态：本地查看与插件辅助审核入库的交互已明确，文件系统集成尚未实现或实测。

## 当前产品决定

用户要求素材查看直接跳转到本地文件，人工审核通过后的文件移动由插件协助完成。素材管理负责打开设置中配置的草稿箱和资产库，并提供“审核入库”操作；图片和视频使用本地文件工具查看，当前不制作插件内的完整媒体浏览界面。

入口仍是扇形菜单中的一个“素材管理”。其内部提供“打开草稿箱”“打开资产库”和“审核入库”操作，查看草稿箱作为优先操作；具体选择面板样式后续细化。“审核入库”不另增为悬浮球扇形菜单入口。

系统文件夹打开的目标体验是使用文件管理器，例如 Windows 资源管理器。配置的是哪个目录，就打开哪个目录，不擅自改为浏览器默认下载目录。

## 打开时的反馈建议

- 目录尚未配置：提示选择相应本地目录，并可前往设置。
- 请求打开目录：实际发送打开请求，失败时说明原因并允许重试；不能只显示“已打开”却没有执行。
- 目录被移动、删除或暂时不可访问：保留原配置，提示重新选择或检查目录，不自动创建替代库。
- 两个“打开目录”操作只用于查看，不触发审核或文件移动；“审核入库”使用单独、明确的用户操作。

## 审核入库：已确认的操作

用户希望由插件将审核通过的文件移到资产库，并明确选择系统文件选择器的方式指定文件，支持多选。

操作：点击“审核入库” → 文件选择器默认打开已配置的草稿箱 → 用户选择认可的文件，可多选 → 确认选择 → 插件将选中文件移入已配置的资产库。

这次选择确认表达用户的审核决定；浏览目录本身不等于审核通过。建议在入口处明确提示“选择的文件将从草稿箱移至资产库”，不再增加一次重复确认弹窗。

移动规则与反馈建议：

- 执行前检查两个目录已经配置且可访问，未配置时提示前往设置，并验证所选文件来自当前草稿箱。只处理本次明确选中的文件，用户取消选择时不移动任何文件。
- 入库必须移动实际媒体文件；存在已绑定来源、备注等元数据时需要保持关联，不能只改变数据库状态或留下失效的文件引用。
- 确认目标文件完整写入后再清理草稿箱中的源文件；写入失败时保留源文件，不能先删源文件再尝试复制。
- 草稿箱与资产库可能位于不同磁盘，跨目录移动、异常中断和重试均需验证。操作未完成时不能显示“已移入资产库”。
- 同名目标文件不能静默覆盖；具体冲突处理方式后续细化。
- 批量移动按文件反馈结果。部分成功时显示成功与失败数量，保留失败文件及原因；重试只处理未完成项目，避免重复入库。

| 状态 | 建议反馈 |
| --- | --- |
| 移动中 | “正在移入资产库…”及实际处理进度 |
| 全部成功 | “已将 N 个文件移入资产库” |
| 部分成功 | “N 个已移入，M 个未完成”，列出未完成文件并提供重试 |
| 未能完成 | 明确原因并允许重试，保留尚未完成转移的文件；目标已写入但源文件未清理时如实说明 |

审核由用户决定，AI 接入继续后置。当前只记录产品行为，没有实际移动用户文件。

## 条目文件夹：正在讨论的调整

用户提出每条素材使用单独文件夹，包含实际媒体和描述。建议在草稿箱与资产库中保持相同结构，审核入库时以整条素材文件夹为单位转移，媒体和描述一起处理。描述内容已确认先包含可确认的来源、收集时间和自由备注；结构命名、描述格式与批量选取方式继续细化，详见 [素材文件夹结构](material-folder-structure.md)。

此前确认的交互是从草稿箱多选文件。若采用分文件夹方案，需要继续明确如何方便地批量选择条目，不能假定原来的文件选择器天然支持跨多个子目录多选，或直接替换成已验证可用的多选文件夹选择器。取消选择、完整写入后清理源数据、失败可恢复的原则继续适用；结果数量按素材条目统计，不把媒体和描述分别算两条。

## 官方能力与实现边界

Chrome Downloads 文档提供 `downloads.show(downloadId)`，作用是在文件管理器中显示一项已下载文件；`showDefaultFolder()` 打开的是默认下载目录。二者均不等于接受任意目录路径并打开。由目录句柄直接写出的文件也不能假定已有对应下载记录。见 [Downloads API](https://developer.chrome.com/docs/extensions/reference/api/downloads)。

Edge 官方支持 Native Messaging，使扩展与已安装的本地程序通信。本地程序需要单独分发与注册，浏览器不会因为装了扩展就自动装好它。见 [Edge Native Messaging](https://learn.microsoft.com/en-us/microsoft-edge/extensions/developer-guide/native-messaging)。

基于这些接口范围的工程判断：要稳定打开用户任意选择的草稿箱和资产库目录，可能需要轻量本地辅助程序。是否必须采用此方案，以及安装负担，仍需技术验证和产品取舍；本轮不自动增加此安装要求。

实现前必须核实：自选目录能否真实打开、空目录能否打开、跨磁盘路径与中文空格路径是否正常、扩展重启后是否可用，以及是否额外依赖本地程序。审核入库还需验证文件选择器以草稿箱为起点、多选、来源校验、完整转移和失败恢复。`file://` 在浏览器中打开目录与打开系统资源管理器属于不同体验，不能混称为同一能力。

当前只记录需求与能力边界，没有安装本地程序、修改注册表或实际打开用户素材目录。
