# Edge 技术验证记录

日期：2026-10-19。环境：Windows、Edge 155.0.4283.62、Python 3.13.8、Node 22.23.2。当前是进行中的实测记录，不是软件发布或三站兼容性声明。

## 控制通道

Windows 窗口控制器先后在扩展地址和普通本地测试页上返回无法可靠识别当前浏览器 URL，未关闭或修改其检查。随后改用已经连接的 Edge 浏览器插件，成功打开并操作 `http://127.0.0.1:43817/dashboard.html`。

该浏览器控制通道只允许 HTTP、HTTPS，自动打开 `edge://extensions/` 被策略拒绝。用户随后手动在当前 Edge 配置加载了本项目测试扩展，测试页已实际收到扩展状态回应。

## 录制授权与快捷键

- 测试扩展已在用户当前 Edge 配置连接成功。
- 首次检查时 `record-selection` 的 `shortcut` 为空；用户手动设置后，`chrome.commands.getAll()` 实际返回 `Ctrl+Shift+9`。这说明必须检测真实绑定状态，不能只展示 manifest 中的默认组合。
- 在一个尚未调用扩展的普通测试标签页，只点击网页按钮开始录制，实际被 `tabCapture` 拒绝：`Extension has not been invoked for the current page (see activeTab permission). Chrome pages cannot be captured.` 不将其误判成用户处于 Chrome 内部页面。
- 网页自动化发送的模拟快捷键没有派发扩展命令；后台错误时间未变化。因此录制开始需要由用户实际按下已绑定快捷键，不能把网页模拟按键当作已经完成授权。

## 首轮真实试录：保存失败与修复

用户已依次在四个测试页面使用真实录制快捷键。自制视频页面及 B站、YouTube、X 三个页面的反馈均已直接读取，错误一致：`Cannot read properties of undefined (reading 'local')`。测试草稿箱尚无 WebM 文件；本轮不能标记为录制通过。

定位到 0.0.1 的 offscreen 录制器在停止、收集媒体 Blob 后调用了 `chrome.storage.local`。offscreen 只支持 `chrome.runtime` 扩展接口，设置应由 worker 查询并通过消息传入。该接口边界的官方依据见 [API 补充笔记](technical-spike-api-notes.md)。

已新增实际消息处理流程的回归检查。在只提供 `chrome.runtime` 的模拟 offscreen 环境中，旧代码稳定复现同一错误；移除不支持的存储调用、由 worker 传入保存模式后，该检查通过。另一个检查发现生成的 Canvas 视频轨未停止，已一并修复为清理源轨、输出轨和音频上下文。

修复版 0.0.2 的五项录制器回归检查通过，覆盖原错误、轨道释放、两种保存路线区分、保存失败反馈及空媒体拒绝保存。它们使用模拟媒体事件，**不代表浏览器媒体编码、三站录像或实际音画通过**。

## 第二轮自制视频：数据编码失败与修复

用户重载 0.0.2 后，再次在自制视频页用真实快捷键录制 2–6 秒。直接读取播放器确认停在 6.025122 秒、已暂停，但页面反馈 `Only base64 data is allowed`，草稿箱仍无 WebM，不能标记保存成功。

原因是 `FileReader` 数据 URL 的媒体类型包含 `codecs=vp9,opus`，旧代码按逗号拆分后，取到的是媒体类型片段而非 Base64 数据。原测试模拟了过度简化的 MIME 类型，因此漏掉此问题。测试现已保留 Blob 的真实 MIME 类型，旧实现稳定失败；改为按 `;base64,` 定位负载后，字节完整性检查及其余录制器回归检查全部通过。修复版为 0.0.3，仍须重载并验收实际文件。

## 第三轮自制视频：实际文件通过，裁切未通过

用户重载 0.0.3 后，真实快捷键启动的 2–6 秒录像实际落盘：媒体 1,269,535 字节，VP9 + Opus，121 帧，源视频在 6.013379 秒暂停，结束原因 `selected-end`。完整解码无错误；运动画面和非静音音轨有效（平均 -21.2 dB）。MediaRecorder 生成的 WebM 没有容器时长字段，改用实际包时间戳量得 4.061 秒，不能因头部无 duration 就误判无时长。开始位置字段目前来自请求的 A，尚不等于对编码首帧的独立测量。

同一标签页获得授权后，通过页面测试按钮再次开始，选区 2–12 秒，主动提前结束于源 10.913214 秒。生成另一条 2,710,859 字节录像，包时间戳长 8.974 秒，结束原因 `manual-button`，音画可解码。此项证明按钮提前结束，不冒充快捷键第二次按下的实测。随后退出选段，直接读取源视频回到 0 秒、暂停，与进入前一致。

抽取首帧却发现录入了播放器上方的一段标题，输出比例也偏离源播放器。原因是 2560×1440 捕捉帧与 1699×828 网页视口比例不同；分别按 X/Y 缩放忽略了居中补边。0.0.4 改用统一缩放和补边偏移，并记录原始捕捉帧与裁切映射。宽视口、窄视口、同比例和无效区域检查已加入，仍须重载后用真实画面验收。当前不标记裁切或三站录制通过。

```powershell
node --test spikes/edge-local-capture/tests/offscreen.test.cjs
py -3.13 spikes/edge-local-capture/inspect_recordings.py
```

后一命令只检查实际本地媒体，不下载站点视频。初次运行报告 `recordingCount: 0` 并以失败状态退出，避免空目录被当作验收成功。
