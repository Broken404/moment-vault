# 视频选段与预录制交互草案

更新日期：2026-10-19。状态：需求细化，尚未实现或进行平台实测。

## 用户已经明确的要求

- 时间线上有起点和终点，两个点均可左右拖动。
- 进入“预录制模式”后，可以用键盘调整两点。
- 快捷键初步示例：方向键按 5 秒移动，Ctrl + 方向键按 1 秒移动；具体按键与步长仍可完善。
- 可以预览整个选定片段。
- 调整起点或终点时有动态预览。
- 动态预览表现已确认：主预览画面跟随所调整的端点；点击独立按钮后播放整个选区。
- 预览窗口比原网页播放器小，是偏小的预览区域；具体尺寸和放置位置尚未确定。
- 操作希望有类似剪辑软件的时间线选段体验。

以下细节是为了形成可讨论的完整流程提出的建议，并非全部已经得到用户确认。

## 1. 预录制模式的含义

建议定义为：在原视频上确定区间、检查边界与试播，确认后再采集该区间。

流程：进入预录制 → 调整起点 A 与终点 B → 预览整个选区 → 确认录制 → 检查结果 → 保存到草稿库。

预录制界面包含较小的预览窗、带两个端点的时间线、起终点与时长读数，以及独立的“预览选区”按钮。较小预览窗作为本界面的主画面，拖动边界时更新该画面。

预览窗建议保留源视频宽高比，横屏、竖屏内容均完整显示。窗口的默认大小、能否缩放、采用网页内浮层还是其他放置方式，留待下一轮界面讨论，不将“小窗”提前解释为另开系统窗口。

这里的范围选择依赖源视频可回看与可跳转。对可回看的内容，用户可以选中刚刚看过的区间，再回放采集。持续维护“过去 N 秒”缓冲仍是另一项待评估能力，不是进入选段模式就已经启动的默认行为。

## 2. 区分两个端点与播放头

- 起点 A：片段开始的位置。
- 终点 B：片段结束的位置。
- 播放头 P：预览当前正在显示的位置。
- 当前选中的端点：明确显示正在修改“起点”还是“终点”。

播放头随预览移动时，不改变起终点。调整端点时，另一个端点保持不动。不要让同一组方向键在没有提示的情况下同时改变选区和播放位置。

时间线应高亮 A 到 B 的范围，并持续显示起点时间、终点时间及选区时长。多个相邻视频或帖子存在时，进入模式前先明确当前源视频，整个选段过程锁定其身份。

长视频建议提供全片位置导航和可缩放的局部时间线，避免在两小时长度的进度条上只能靠鼠标猜测秒级位置。是否显示缩略图轨道、如何获取画面，需要另行验证。

## 3. 键盘与鼠标建议

| 操作 | 建议行为 |
| --- | --- |
| 点击起点或终点 | 选中该端点，视觉高亮并显示当前操作对象 |
| 拖动端点 | 修改所拖端点，同时更新其时间与选区时长 |
| → / ← | 当前选中端点向后 / 向前移动 5 秒 |
| Ctrl + → / ← | 当前选中端点向后 / 向前移动 1 秒 |
| 长按方向键 | 随重复按键事件连续累计调整，画面跟随最新目标位置 |
| 点击“预览选区” | 总是从 A 开始播放，到 B 停止 |
| 空格 | 暂停 / 继续选区预览；预览已经结束时可从 A 重播 |
| Escape | 取消当前拖动，或退出预录制；具体层级行为待交互原型验证 |

按键规则仅在选段编辑区域获得焦点时生效；备注输入框、搜索框等文本编辑区域保留正常按键行为。需要防止原网页播放器同时响应同一按键，导致位置被额外跳转。

步长 5 秒和 1 秒按用户示例记录为初始建议。更细的步长、自定义设置及逐帧调整后续再定，不把“类似剪辑软件”解释为完全复制某款软件的快捷键。

## 4. 调整端点时的动态预览

已确认：鼠标或键盘调整边界时，较小预览窗的主画面跟随到该端点；整个选区通过独立按钮播放。

据此建议：调整时显示对应位置的画面，定位后暂停，保持边界判断稳定。调整动作不自动播放端点附近片段。界面遵守以下原则：

- 操作开始时暂停正在进行的选区试播，避免预览播放和端点调整争抢同一播放器。
- 端点读数及时更新，实际画面未到位时显示“正在定位”，不把旧画面当作新位置的预览。
- 连续快速移动时优先处理最新位置，旧请求完成后不能让画面倒退到过期目标。
- 松手或停止按键后，应最终定位到最新端点，并显示真实对应画面。
- 单次静止画面预览建议保持静音；完整选区预览保留声音，便于判断对白、音乐和转场。此项仍为建议。

小预览窗不要求复制原网页播放器的完整控件。原网页播放器是否同步跳转、是否暂停以及退出后如何恢复，应与预览的具体实现一起验证，不能先承诺两个播放器可以完全独立运行。

## 5. 整段预览

“预览选区”从 A 开始，到 B 自动停止。建议首版先单次播放，循环预览可作为独立开关。

预览中修改 A 或 B 时，暂停并回到调整状态，下一次完整预览使用新范围。预览不产生资产文件，不将选区自动标记为已采集或正式入库。

预览与最终录制应使用相同的源视频身份与范围；进入录制前重新检查，防止平台站内导航、分集切换或帖子切换后仍沿用原区间。

## 6. 边界与失败规则

- A 必须早于 B，二者不能交叉；建议遇到边界就停止移动，不自动交换起终点或推走另一个端点。
- 区间必须位于当前可回看范围内；直播、内容失效或回看范围变化后，需要重新检查。
- “可回看范围”与“当前已经缓存的范围”不同，不能只因为尚未缓存就把有效区间排除。
- 最短片段长度、最长片段长度与初始区间如何生成，尚待确定，不擅自定为用户要求。
- 多次按键应累计改变端点；预览定位可以合并，不能因为网络慢就丢弃用户输入的时间调整。
- 录制过程中先锁定 A/B；要修改则返回选段状态，避免选中范围与所得片段不一致。
- 视频不可定位、广告切入、换集、缓冲失败或来源变化时，保留已选区间并明确告知，不显示录制成功。
- 退出模式后的原播放位置、播放速度与播放/暂停状态如何恢复，列为待确认的体验细节。

## 7. 从选区到真实片段

产品目标：用户预览确认的区间，与最终保存片段的内容一致。

若采用实时回放录制，需要定位到 A，等待视频画面与采集链路就绪，回放选区，到 B 附近结束并检查所得文件。需要验证开始/结束偏差、音画同步、缓冲中断和播放器叠加层，不能简单按 B-A 的墙钟时间结束录制。

最终片段应包含视频内容，避免把选段面板和时间线一起录入。具体选用何种捕捉、裁剪或后处理方案，仍需技术试验。

选择区间和生成媒体文件分开验收。原视频时间范围、实际媒体文件时长及采集方式分别保存，不能把端点显示到毫秒视为帧级精确导出已经成立。

## 8. 官方依据与实现限制

- 修改 `currentTime` 可请求跳转到视频时间；能否到达目标位置取决于媒体是否可用。见 [MDN currentTime](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/currentTime)。
- `seekable` 提供当前可定位的时间范围，可用于检查端点有效性。见 [MDN seekable](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/seekable)。
- `seeked` 表示一次定位操作完成；连续交互仍需要自行管理最新目标和显示状态。见 [MDN seeked](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/seeked_event)。
- `requestVideoFrameCallback()` 可获取提交显示的视频帧时间信息，可辅助确认预览画面；这不自动提供精确剪辑与导出能力。见 [MDN requestVideoFrameCallback](https://developer.mozilla.org/en-US/docs/Web/API/HTMLVideoElement/requestVideoFrameCallback)。
- `timeupdate` 的触发频率受负载影响，不能单凭它承诺精确到帧的终点停止。见 [MDN timeupdate](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/timeupdate_event)。

这些是浏览器层面的能力依据；B站、YouTube、X 的具体页面操控、可回看性和预览流畅度仍未实测。

## 9. 待实现后的验收情境

1. 选中起点，按方向键 → 只让 A 增加 5 秒；Ctrl + ← 让 A 减少 1 秒；B 保持不变。
2. 改选终点后，相同按键只修改 B，并保持选区合法。
3. 长按或快速来回拖动后，时间读数及小预览窗的最终画面落在最后一次操作的位置，调整动作不自动开始试播。
4. 预览从 A 开始、到 B 停止，A/B 不随播放头移动。
5. 播放过程中编辑端点会退出当前试播，下一次预览使用新范围。
6. 选区临近视频开头、结尾或不可回看位置时，界限和错误可理解。
7. 备注输入时方向键不触发时间调整，网页播放器也不会重复处理已被编辑器接管的按键。
8. 横屏和竖屏内容在较小预览窗中保持宽高比；预览窗大小与原播放器大小分别处理。
9. 录制结果能回放，并检查其内容与预览区间是否一致；失败不晋级为已采集。
