# 视频选段与预录制交互草案

更新日期：2026-10-20。状态：正式交互继续细化，核心录制路线已取得普通视频样本的实测证据，具体覆盖与遗留问题见 [技术验证记录](technical-spike-results.md)，不代表本篇完整交互已经实现。

首版范围已确认：B站、YouTube、X 的可暂停、可回看视频，覆盖横屏与竖屏，直播不需要。整体流程和默认值以 [首版产品与技术方案](formal-plan.md) 为准。

最新界面要求：用户希望把起点 A、终点 B 直接放到原播放器已有的进度条上拖动，认为最初技术试验中的独立滑条体验一般，并进一步明确备用形式只能迫不得已才用。正式方案将原进度条上的可拖动标记和选区高亮列为三站目标页面的首版验收要求，不以独立滑条或临时精调代替完成；用户明确保留独立预览窗，不改为在原视频画面中完成预览，并强调视频缓存与卡顿是关键体验问题。原进度条适配和独立预览的缓存复用均需新增验证，现有三站录制证据不证明这两项能力已经通过。

用户已确认录制开始后将完整选段界面收起，改为视频画面外的小状态条，显示“录制中”、已录时长及提前结束快捷键。准备和定位阶段仍须如实显示准备状态，真实录制开始后才显示录制中；不是隐藏全部录制提示。

最新原则：用户选好 A/B 区间后，按录制快捷键，从起点 A 开始录制，到终点 B 自动结束；中途可再次按同一快捷键提前结束。停止后直接将实际视频文件保存到草稿箱，审核后才能成为资产。选段与试播不启动录制，不进行隐蔽后台录制或持续缓冲。本次明确了选段与录制的衔接，更新此前“开始和结束均必须手动操作”的约定。

## 用户已经明确的要求

- 时间线上有起点和终点，两个点均可左右拖动。
- 进入“预录制模式”后，可以用键盘调整两点。
- 方向键默认按 5 秒移动，Ctrl + 方向键默认按 1 秒移动；两个时间步长均可在设置中修改。
- 可以预览整个选定片段。
- 调整起点或终点时有动态预览。
- 动态预览表现已确认：主预览画面跟随所调整的端点；点击独立按钮后播放整个选区。
- 已明确保留较小的独立预览窗，位于当前网页内，可拖动、可调整大小；A/B 在原播放器进度条上操作，边界画面与整段试播集中在独立预览窗，不新增浏览器或系统独立窗口。
- 预录制模式默认关闭，可以随时调用和关闭，避免影响正常观看；选段窗和录制小状态条均须保留关闭入口，关闭后不因异步结果再次弹出。
- 已确认提供独立、可自定义的“打开／关闭录制模式”快捷键，与开始 / 提前结束录制的快捷键分别设置；唤出模式不自动开始采集。
- 关闭预录制模式后，回到进入预录制前的观看位置，此项已由用户明确确认。
- 操作希望有类似剪辑软件的时间线选段体验。
- 选好区间后通过快捷键主动开始录制；到终点自动结束，也可通过快捷键提前结束，产品不进行隐蔽后台录制。
- 草稿箱直接保存可查看的视频文件，所有素材审核后才进入资产库。
- 保存的视频片段主要交给 Codex、Claude 做参考，成片采用 MP4（H.264、AAC），保留实际录到的画面与声音。当前不加入 AI 分析或上传功能。

以下细节是为了形成可讨论的完整流程提出的建议，并非全部已经得到用户确认。

## 1. 预录制模式的含义

建议定义为：在原视频上确定区间、检查边界与试播，确认后再采集该区间。

选段与预览继续按已确认的 A/B 交互设计。用户按录制快捷键后，从 A 回放并录制，到 B 自动结束；中途可用快捷键提前结束。结束后直接保存视频文件到草稿箱，供稍后查看与审核；不要求先完成一次额外检查确认才落地草稿。

选段界面沿用原播放器的进度条，叠加起点 A、终点 B 与选区高亮，保留起终点和时长读数，以及明确的“预览选区”操作。拖动端点时及时更新其时间，独立预览窗显示对应边界画面；缓存和定位尚未就绪时明确显示加载状态，不把旧画面当作新位置。

独立预览窗的布局与操作已通过整合预览，采用暖纸色、深灰、黄色强调与轻像素切角；以当前预览的 330 px 宽度为紧凑参考，根据视口调整，正式版仍可拖动和调整大小。画面保持源视频宽高比，兼顾横屏与竖屏，早期 480 px 不再作为当前默认参考。窗口不另建一套常驻的重复时间线，原播放器进度条承担主要选段操作。

已通过的排布：原进度条上的 A/B 标记上下错开，便于靠近时分别选中；独立窗从上到下显示边界画面、定位状态、起终点时间卡片、选区时长、“预览选区”、默认收起的“精细调整”及实际录制快捷键提示。选中 A/B 后，两处的当前端点高亮与时间保持同步；完整试播和录制分别表达。

### 模式开关与观看恢复

已确认的体验目标：用户需要时随时打开预录制模式，也能随时关闭，关闭后回到进入前的观看位置，能够继续使用原网页播放器。用户再次强调随时调用与关闭，避免模式影响看视频；退出不能要求先等文件处理完成。

为落实这一目标，采用以下操作规则；其中保留未完成选区的细节仍按第 7 项建议处理：

1. **默认关闭**：浏览视频时不自动展开选段窗，关闭状态不接管播放器快捷键，也不在后台继续预览、定位或采集。
2. **进入时记录状态**：保存源视频身份和进入时播放位置；同时记录播放/暂停状态以及扩展随后可能临时修改的播放设置。该观看位置与选段起点 A、终点 B 分开保存。
3. **进入时建议暂停原视频**：避免选段过程中原视频仍在向前播放，以及原画面与选区试播同时发声。独立预览窗表示显示区域独立，不承诺原视频同时继续播放，也不预设必须另建一套视频下载与解码链路；缓存与帧输出复用需按下文逐站验证。
4. **窗内操作有明确范围**：调整尺寸和拖动窗口位置不改变 A/B；时间线交互只改变所选端点或预览播放头。悬浮窗外的页面仍能滚动和点击，不使用遮罩锁住整页。
5. **关闭即退出模式**：开启后，桌宠菜单中的对应入口提供退出操作；预览窗和录制小状态条均有关闭入口，与模式开关的关闭动作语义一致。关闭时移除选段窗、A/B 标记与选区高亮，停止选区试播，取消未完成的预览定位，移除快捷键接管与页面拦截，释放只用于预览的媒体资源。
6. **恢复观看**：在仍为同一源视频的前提下，回到进入前的位置；建议原本播放则继续播放，原本暂停则保持暂停。扩展临时更改过的倍速、音量等设置按记录恢复，避免试播影响后续观看。
7. **关闭不等于保存或删除**：未录制的选区不能显示成已采集资产。建议在当前页面内保留未完成选区信息，供再次打开时继续；再次使用前重新检查来源和区间有效性。
8. **来源变化不乱恢复**：若用户已经切换视频、分集或帖子，不能把旧视频的观看时间写到新视频上。原内容无法恢复时明确提示，关闭后的旧定位请求也不能再干扰当前观看位置。

关闭模式必须真正停止其交互与预览行为，不能只隐藏悬浮窗而保留对原播放器的控制。反复调用和关闭时不能叠加事件处理，旧会话的定位请求或保存回调不能改变新的观看位置，也不能重新打开用户已关闭的模式。

准备阶段关闭则取消尚未开始的采集；已经录制时关闭则先停止采集、保存已录部分并退出，待采集停止即可恢复观看，不要求等转码和写盘完成。处理保存阶段仍能关闭界面，文件保存继续，结果通过不遮挡视频的轻提示反馈，失败保留可恢复内容与重试入口。关闭后不自动重新展开选段窗，不能静默丢弃已录内容或隐藏后继续录制。

这里的范围选择依赖源视频可回看与可跳转。对可回看的内容，用户可以选择已经看过的区间并试播，再用快捷键主动开始该区间的回放录制。当前不规划持续维护“过去 N 秒”的后台缓冲。

## 2. 区分两个端点与播放头

- 起点 A：片段开始的位置。
- 终点 B：片段结束的位置。
- 播放头 P：预览当前正在显示的位置。
- 当前选中的端点：明确显示正在修改“起点”还是“终点”。

播放头随预览移动时，不改变起终点。调整端点时，另一个端点保持不动。不要让同一组方向键在没有提示的情况下同时改变选区和播放位置。

时间线应高亮 A 到 B 的范围，并持续显示起点时间、终点时间及选区时长。多个相邻视频或帖子存在时，进入模式前先明确当前源视频，整个选段过程锁定其身份。

原播放器的进度条作为默认的全片位置与范围选择入口。用户已明确接受在独立预览窗中提供默认收起的“精细调整”，展开后放大当前端点附近的时间范围，解决长视频中短选区太窄、A/B 靠近或重叠而难以拖准的问题；它是首版功能，不作为后续优化推迟。原进度条仍是日常入口，局部精调不常驻展开。

精调布局与操作现已通过预览：展开后围绕当前端点显示附近 20 秒，提供放大、缩小、局部拖动和直接输入时间；A/B 时间卡片用于切换当前编辑对象。按当前预览的 2–120 秒作为局部缩放范围的实施取值，缩放与切换本身不改变 A/B，端点接近片头或片尾时限制在可回看范围内。此前附近 30 秒的建议被本轮预览取代。

原进度条、精调区域与 A/B 读数共用同一组选区，调整任一处都保持同步，另一个端点不因编辑而被自动推走。输入无效时间或越过另一端点时明确提示，保留有效选区；文本输入过程中不接管方向键。既有方向键 5 秒、Ctrl＋方向键 1 秒的默认步长保留，不生成整片缩略图轨道。

### 原进度条适配的实现与验收边界

技术选择是通过扩展内容脚本，在播放器现有进度条附近叠加自己的 A/B 操作层，沿用原播放器的播放能力。扩展修改网页内容的基础见 [Content scripts](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)，拖动期间持续跟踪指针可使用 [Pointer capture](https://developer.mozilla.org/en-US/docs/Web/API/Element/setPointerCapture)。这些能力支持实现方向，不等于三站已经适配成功。

B站、YouTube、X 分别维护小型适配器，负责视频身份、播放器外壳、真实完整轨道、时间映射及生命周期；A/B 状态、拖动、键盘、精调、预览和退出恢复共用一套控制器。默认使用隔离内容脚本与 DOM，不依赖未证实稳定的网页私有播放器 API；网站改版时主要修对应适配器，不在通用采集逻辑中散落各站页面结构判断。

2026-10-20 在 in-app browser 现场检查的三个公开样本均找到了原轨道结构：B站完整轨道没有 slider 角色；YouTube 同时有播放、音量和精确跳转滑块；X 的控件在交互后出现，slider 本身仅是播放头，外层才是完整轨道。观察说明不能因首次查找失败或误选节点就降级，不证明 Edge 扩展集成已通过。样本与限制见 [现场 DOM 记录](evidence/native-timeline-dom-2026-10-20.json)，浏览器能力、实现建议与详细验收见 [适配研究](native-timeline-research.md)。

实施先确认当前视频和所属播放器，再结合每站有限的结构、语义线索查找并验证真实轨道，排除音量、播放头、缓冲长度、局部片段和其他视频。按实际轨道矩形与经校验的时间域映射 A/B；覆盖层依附稳定外壳，隔离样式，不靠播放器底部的固定偏移猜位置。端点接管自身拖动并在结束、取消或退出时释放，原播放头和其他按钮继续可用。

控制栏自动隐藏、延迟挂载和节点重建属于需要处理的正常生命周期。采用限定范围的节点观察、尺寸观察以及滚动和布局事件，合并更新几何；发现绑定失效时先保留同视频 A/B、暂停不可信坐标上的拖动，再按下列路径恢复：

1. 等当前视频元数据和播放控件准备，必要时提示用户将鼠标移到播放器，重新识别同一播放器的轨道，不将暂时隐藏记为不支持。
2. 对已验证的站点机制，在选段期间临时保持原轨道可见；尺寸、滚动或影院布局变化后重新测量，控件重建后重新绑定。退出和开始真实录制时撤销这类选段专用修改。
3. 核对实际播放器所在的可注入 frame 与可访问结构，使用该站其他已验证候选规则；重试有界并由相关页面变化触发，不无限轮询或永久扫描整页。换视频则解除旧绑定、重新初始化，不把旧 A/B 或观看位置应用到新视频。
4. 上述恢复确实失败且媒体仍可定位时，说明原进度条暂不可连接，提供“重新连接”和可选的“临时使用精调”，由用户选择；不自动展开备用布局。若媒体本身不能回看或定位，则如实说明，精调不能冒充解决办法。

首版必须在三站目标页面分别通过原轨道 A/B 拖动、键盘同步、长视频短选区、隐藏与重建恢复、滚动和影院布局，以及独立预览和实际录制联动检查；叠加控件不能混入成片。临时精调通过不能算原轨道通过，未通过项继续修复或明确列为未交付；支持矩阵按真实验收页面类型记录，不提前宣称平台所有页面均可用。精调的日常用途仍是已确认的长视频精确调整补充。

## 3. 键盘与鼠标建议

| 操作 | 建议行为 |
| --- | --- |
| 点击起点或终点 | 选中该端点，视觉高亮并显示当前操作对象 |
| 拖动端点 | 修改所拖端点，同时更新其时间与选区时长 |
| → / ← | 当前选中端点向后 / 向前移动 5 秒 |
| Ctrl + → / ← | 当前选中端点向后 / 向前移动 1 秒 |
| 长按方向键 | 随重复按键事件连续累计调整，画面跟随最新目标位置 |
| 点击“预览选区” | 总是从 A 开始播放，到 B 停止 |
| 空格 | 暂停 / 继续选区预览；预览已经结束时可从 A 重播 |
| 模式开关快捷键（独立可配置命令，默认未绑定） | 关闭状态下进入选段，开启状态下退出；录制中退出先停止采集并保存已录内容，再按关闭流程恢复观看 |
| 录制快捷键（建议默认 Ctrl＋Shift＋9，以浏览器实际绑定为准） | 已有有效选区时，从 A 开始录制；录制中再次按下则提前结束并保存 |
| Escape | 建议先取消正在进行的拖动；未拖动时退出预录制，与关闭按钮使用同一恢复流程 |
| 关闭按钮 / 关闭模式开关 | 退出预录制并恢复进入前的观看位置 |

方向键、空格等局部编辑按键仅在选段编辑区域获得焦点时生效；备注输入框、搜索框等文本编辑区域保留正常按键行为。模式开关与实际录制通过独立的扩展命令处理，按当前目标与任务状态执行，不依赖预览窗先获得焦点；需要防止原网页播放器重复处理已接管的按键。

用户已确认模式开关快捷键与实际录制快捷键分开，均可在设置中查看实际绑定并前往 Edge 修改；模式开关沿用其他命令默认未绑定。它们也与调整端点的方向键分开。长按产生的重复事件不能让模式反复开关，或把一次录制开始误判为立即结束；停止和保存过程中重复按键不得创建重复录制或重复文件。

默认步长 5 秒和 1 秒已作为设置要求明确，用户可分别修改，界面读数与实际调整均使用当前配置；表格展示默认行为。逐帧调整后续再定，不把“类似剪辑软件”解释为完全复制某款软件的快捷键。详见 [设置草案](settings.md)。

## 4. 调整端点时的动态预览

已确认：鼠标或键盘调整边界时，较小预览窗的主画面跟随到该端点；整个选区通过独立按钮播放。

据此建议：调整时显示对应位置的画面，定位后暂停，保持边界判断稳定。调整动作不自动播放端点附近片段。界面遵守以下原则：

- 操作开始时暂停正在进行的选区试播，避免预览播放和端点调整争抢同一播放器。
- 端点读数及时更新，实际画面未到位时显示“正在定位”，不把旧画面当作新位置的预览。
- 连续快速移动时优先处理最新位置，旧请求完成后不能让画面倒退到过期目标。
- 松手或停止按键后，应最终定位到最新端点，并显示真实对应画面。
- 单次静止画面预览建议保持静音；完整选区预览保留声音，便于判断对白、音乐和转场。此项仍为建议。

小预览窗不要求复制原网页播放器的完整控件。若预览依赖对原播放器的定位操作，必须满足关闭后回到进入前观看位置的已确认要求；建议进入时暂停、关闭时恢复原播放状态。两个播放器是否可以独立运行仍需技术验证。

### 4.1 缓存与响应：本轮新增重点

用户已明确要求重视视频缓存，避免独立预览窗的卡顿影响选段体验。独立预览的实际性能需作为正式路线的专项验收，不能只凭界面动画或录制链路通过判断。

实施方选择优先验证“复用原播放器的已加载内容和解码帧，在独立窗呈现，另加少量近期预览画面缓存”的路线。这样尽量减少重复下载与解码，沿用现有浏览器媒体能力，不先引入独立下载器、第二套流媒体播放器或自建持久视频缓存。窗口的独立显示与视频流、缓存能否复用是不同问题，不能简单复制 `src` 或克隆 video 元素就宣称复用成功；如果某站无法可靠复用，应保留为未解决项，另行验证可行路线。

以下是技术选型与实施要求，尚非已实测性能结论：

- 分开处理选区更新与媒体定位。A/B 标记和时间读数及时响应，媒体定位采用合并请求与单次定位调度；已有请求尚未完成时仅保留最新目标，过期请求的画面不得覆盖新位置。取消旧预览表示取消其展示和后续调度，不宣称浏览器一定已取消底层网络请求。
- 分清 `seekable` 和 `buffered`：前者是当前可跳转范围，后者才是当前已缓冲范围，两者都要读取当时的实际值。未缓存的合法区间仍可选择，不能伪装成已缓存，也不能仅因未缓存而禁选。
- 在当前选段会话内按源视频身份、帧实际时间与画面尺寸暂存近期预览帧，采用有容量上限的最近使用淘汰方式，优先保留 A/B 边界，避免同一位置反复解码。源码、分集、清晰度或尺寸发生相关变化时失效对应缓存，退出后释放。
- 选区稳定后可在站点实际允许的范围内准备边界和即将试播的少量内容；不要求用户等整段或整片缓存完成，不持续预取远离当前选区的内容，不与正在进行的定位争抢播放器。
- 新画面只有在定位与帧呈现得到确认后才更新为当前边界结果。可利用 `requestVideoFrameCallback` 的实际帧时间核对；不能仅以设置了 `currentTime`、收到某个旧的 seeked 或读取到一张旧画面判断新位置已就绪。
- 缓存未命中时显示“正在加载/正在定位”和目标时间，标记仍可继续移动；如保留上一张画面，明确标为上一预览，不把它标成新边界。加载失败保留 A/B，提供重试。
- 所有缓存与提前准备只服务于用户已打开的选段会话，关闭时停止后续调度并释放资源，不构成后台持续录制或自动保存素材。

用户已接受的交互：拖动期间优先保证跟手，有限频地提供已就绪的快速预览；松手后针对最终位置完成准确定位，尚未得到该位置真实画面时继续显示定位提示。缓存画面若只是邻近位置，必须与最终边界结果分开标注，不冒充精确结果。这是交互取舍的确认，不代表三站实际拖动与缓存性能已通过验收。

依据：[seekable](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/seekable)、[buffered](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/buffered) 与 [requestVideoFrameCallback](https://developer.mozilla.org/en-US/docs/Web/API/HTMLVideoElement/requestVideoFrameCallback)。它们支持上述实现设计，不证明 B站、YouTube、X 已实现共享缓存或无卡顿预览。

专项验收覆盖：已缓存区域反复拖动、未缓存区域跳转、长距离快速往返、A/B 交替调整、长按方向键、弱网下的整段试播、切视频/清晰度、关闭后资源释放。记录标记响应、有效画面呈现与最终定位耗时、缓冲次数及内存使用；三站分别记录实际结果，尚未缓冲的网络数据不能承诺零等待。

精调专项验收还须覆盖长视频中的短选区、原进度条上 A/B 标记靠近或重叠、端点接近视频首尾，以及原进度条和局部精调之间的来回操作；不能仅在短视频中证明两个标记可拖动就视为通过。

## 5. 整段预览

“预览选区”从 A 开始，到 B 自动停止。建议首版先单次播放，循环预览可作为独立开关。

预览中修改 A 或 B 时，暂停并回到调整状态，下一次完整预览使用新范围。预览不产生资产文件，不将选区自动标记为已采集或正式入库。

预览与实际录制必须核对源视频身份，防止平台站内导航、分集切换或帖子切换后仍沿用旧来源。无论试播当前停在哪里，按录制快捷键都从 A 开始；到 B 自动结束或由用户提前结束。选定范围与实际采集范围分别如实记录。

## 6. 边界与失败规则

- A 必须早于 B，二者不能交叉；建议遇到边界就停止移动，不自动交换起终点或推走另一个端点。
- 区间必须位于当前可回看范围内；直播、内容失效或回看范围变化后，需要重新检查。
- “可回看范围”与“当前已经缓存的范围”不同，不能只因为尚未缓存就把有效区间排除。
- 初始选区从当前播放位置向后取最多 5 秒，已在结尾时取最后最多 5 秒；选区不另设业务时长上限，A 必须早于 B，实际受可回看范围、磁盘空间及有效媒体产出约束。
- 多次按键应累计改变端点；预览定位可以合并，不能因为网络慢就丢弃用户输入的时间调整。
- 录制过程中先锁定 A/B；要修改则返回选段状态，避免选中范围与所得片段不一致。
- 视频不可定位、广告切入、换集、缓冲失败或来源变化时，保留已选区间并明确告知，不显示录制成功。
- 退出后回到进入前观看位置已经确认；恢复原播放/暂停状态及扩展临时修改的设置作为配套建议。若原视频已不可回看，应说明无法恢复，不能伪造恢复成功。

## 7. 从选区到真实片段

产品目标：用户预览确认的区间，与最终保存片段的内容一致。

已明确的操作：

1. 用户调整 A/B，需要时通过“预览选区”检查内容。
2. 按录制快捷键，核对源视频与选区，从 A 定位并开始回放录制；不能直接从当前预览播放头位置开始。
3. 录制期间保持可见的录制状态与已录时长，锁定 A/B。到 B 自动结束，不要求用户再按一次结束键。
4. 若想中途结束，再按同一个快捷键，停止并保存从 A 到实际停止位置的内容，不能把尚未录到的后半段算入文件。
5. 停止后直接保存到草稿箱，完成后反馈结果；没有产生有效媒体时不得显示保存成功。只有再次主动开始才会产生下一条录制，不自动循环采集。

“准备录制”“录制中”“正在保存”“已存入草稿箱”和失败状态需要区分。定位或权限准备尚未完成时不能提前显示已经开始录制。仅打开模式、调整选区和试播均不采集。

已通过的录制显示规则：真实录制开始后收起完整选段界面，使用视频画面外的小状态条，显示录制中、已录时长、提前结束快捷键和关闭入口；A/B 保持锁定，选段标记不作为录制中的编辑入口。

已确认的结束规则：到 B 正常结束或用录制快捷键提前结束，实际保存成功后恢复独立预览窗，保留原 A/B，提示“已存入草稿箱”，供用户继续调整与收集；不自动开始下一条。用户手动关闭时恢复进入前的观看状态。若在准备、录制或保存阶段已主动关闭，则以退出意图为准，按上述停止与保存规则恢复观看，保存结果不得自动重新打开模式。

停止后将可播放的视频文件直接保存到草稿箱，不只记录区间、封面或来源链接；文件落地成功后显示已保存，用户稍后可在草稿箱中查看。审核通过后才进入资产库。需要验证音画同步、媒体文件完整性及保存失败后的重试。

最终片段应包含视频内容，避免把选段面板和时间线一起录入。具体选用何种捕捉、裁剪或后处理方案，仍需技术试验。

选择区间和生成媒体文件分开验收。原视频时间范围、实际媒体文件时长及采集方式分别保存，不能把端点显示到毫秒视为帧级精确导出已经成立。

### 成片输出的技术决定

首版成片采用 MP4，视频编码 H.264，存在有效音轨时采用 AAC。浏览器先按录制能力产生中间文件，再由本地助手调用 FFmpeg 完成成片；不通过修改扩展名伪装格式。转换时保留捕捉画面的宽高比和实际声音，不额外放大低分辨率画面。转换与写入期间显示处理中，最终成片与描述落盘成功后才显示已存入草稿箱。

转换失败保留可恢复的中间文件并提供重试，不丢失已经录到的内容。成片需验证完整解码、时长信息、拖动定位、运动连续性和音画一致性。现有技术试验验收的是 WebM，正式 MP4 流程仍需实现和验收。

文件格式服务于本地复用，不预设所有 AI 客户端都可直接读取整段视频；后续 AI 工作流使用完整片段还是按需提取画面与声音，留到接入阶段确定。

## 8. 官方依据与实现限制

- 修改 `currentTime` 可请求跳转到视频时间；能否到达目标位置取决于媒体是否可用。见 [MDN currentTime](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/currentTime)。
- `seekable` 提供当前可定位的时间范围，可用于检查端点有效性。见 [MDN seekable](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/seekable)。
- `seeked` 表示一次定位操作完成；连续交互仍需要自行管理最新目标和显示状态。见 [MDN seeked](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/seeked_event)。
- `requestVideoFrameCallback()` 可获取提交显示的视频帧时间信息，可辅助确认预览画面；这不自动提供精确剪辑与导出能力。见 [MDN requestVideoFrameCallback](https://developer.mozilla.org/en-US/docs/Web/API/HTMLVideoElement/requestVideoFrameCallback)。
- `timeupdate` 的触发频率受负载影响，不能单凭它承诺精确到帧的终点停止。见 [MDN timeupdate](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/timeupdate_event)。

这些是浏览器层面的能力依据；B站、YouTube、X 的具体页面操控、可回看性和预览流畅度仍未实测。

## 9. 待实现后的验收情境

1. 选中起点，按方向键 → 只让 A 增加 5 秒；Ctrl + ← 让 A 减少 1 秒；B 保持不变。
2. 改选终点后，相同按键只修改 B，并保持选区合法。
3. 长按或快速来回拖动后，时间读数及小预览窗的最终画面落在最后一次操作的位置，调整动作不自动开始试播。
4. 预览从 A 开始、到 B 停止，A/B 不随播放头移动。
5. 播放过程中编辑端点会退出当前试播，下一次预览使用新范围。
6. 选区临近视频开头、结尾或不可回看位置时，界限和错误可理解。
7. 备注输入时方向键不触发时间调整，网页播放器也不会重复处理已被编辑器接管的按键。
8. 横屏和竖屏内容在较小预览窗中保持宽高比；预览窗大小与原播放器大小分别处理。
9. 快捷键启动后从 A 录制，到 B 自动结束，草稿箱中能直接播放实际视频文件；文件保存失败不显示成功，也不进入资产库。
10. 预录制默认关闭；打开与关闭均不创建新窗口，悬浮窗可调整大小，窗外页面仍可正常交互。
11. 进入时记下观看位置，调整端点并播放选区后关闭，原视频回到进入前的位置；检查原本播放和原本暂停两种状态。
12. 关闭后方向键重新交还原网页播放器，没有残留试播声音、定位回跳或持续采集；反复开关不会叠加事件处理。
13. 切换视频、分集或帖子后关闭，不把旧来源的时间强行应用到新来源。
14. 拖动悬浮窗或调整大小只改变布局，不改变选段范围与来源身份。
15. 显示悬浮球、打开预录制、拖动端点和试播均不启动录制；只在用户按录制快捷键后开始，不存在隐蔽后台录制。
16. 预览暂停在区间中间时按录制快捷键，仍从 A 开始；中途再次按下会提前结束并保存实际录到的部分，保留原选区与实际范围的区别。
17. 长按录制快捷键不会立刻结束，停止或保存中重复按键不产生重复任务；自动结束后不会自行开始下一次录制。
18. 到 B 或快捷键提前结束后，处理中不冒充保存成功；成功后恢复独立预览窗与原 A/B。随后手动关闭才恢复进入前的观看状态，不自动开始下一段。
19. 准备、选段、试播、录制和处理保存阶段均能关闭：未开始采集时取消准备，录制中先停止采集再恢复观看，转码和写盘继续完成；不要求用户等保存完成才能看视频，已关闭界面不因结果回调再次展开。
20. 快速反复开关或关闭后重新进入，旧定位、旧保存结果不会接管新会话，原播放器方向键和控制条在退出后正常工作。
21. 用真实模式开关快捷键调用时仅进入选段，不开始录制；再次按下退出并恢复观看，录制中按下则停止采集并保存已录部分。分别检查未绑定、绑定冲突、长按及与录制快捷键的区分，不能用网页模拟事件代替浏览器命令验收。

本轮只记录与完善方案，未新增扩展代码或可操作原型。
