# 正式录制与 MP4 保存联动

2026-10-23：正式扩展与新开发助手的实际录制到 MP4 草稿已打通。真实 YouTube 样本完成到 B 自动停止、快捷键提前结束及录制中关闭模式三条保存路径。启动优化后，同一 2～4 秒选区的容器余量从约 0.508 秒降至 0.101 秒；后续曾出现 0.151 秒的长选区失败。进一步移除已暂停源的重复停止确认后，新 2～18 秒样本余量为 0.039899 秒，通过未变更的 0.12 秒比较门槛。原失败保留，单一样本不代表普遍精度保证。旧短片停帧及保存后预览超时仍为独立质量项；三站完整验收和逐帧精确裁剪未通过。

## 用户流程

从桌宠的“屏幕录制”进入，在原时间条上选择 A/B，通过独立窗口确认边界。页面按钮只负责选段和预览；真正录制必须按 Edge 分配给正式扩展的录制快捷键。若试验扩展先占用相同快捷键，需要在 `edge://extensions/shortcuts` 给正式扩展重新绑定，关闭试验版不保证自动转移绑定。

开始前先检查目录和配套视频工具，定位 A 并锁定来源、位置和视口。持久化任务后，确认 `MediaRecorder.start()` 已同步进入 recording 即播放源视频，不再等异步 start 事件；保留不阻塞播放的启动超时保护。状态保存与通知不阻挡开始播放、暂停和停止采集。到 B 暂停并自动结束，也可用同一快捷键或“结束并保存”提前结束。关闭模式先停止采集并等待最后一块落入本地暂存，再恢复观看；MP4 转换在后台继续，不让用户等待转换才退出。

录制时隐藏桌宠、选段窗口、A/B 与目标播放器的原生控制条；小状态条放在视频外。准备时先渲染，按实际尺寸重新定位后检查交叠，文字限制为单行，防止状态变化撑高。当前只支持一项正在录制或保存的任务。页面隐藏、来源改变、播放器或视口移动会结束当前片段，避免继续采集错误区域；完整视频必须处于可见范围。

## 模块与恢复边界

- 服务工作线程只在实际扩展命令中获取标签页采集 ID，协调准备、录制、停止和保存状态。普通网页不能通过消息启动采集。
- Offscreen 页面拥有标签音视频流，以 Canvas 裁剪视频区域并保留标签声音。录制路线延续既有基线，没有将它描述为旧停帧的根因修复。
- MediaRecorder 每 500 ms 形成 WebM 块，按序写入扩展 IndexedDB。上传按 192 KiB 分片，逐片等待助手确认；丢失确认后沿用同一上传和分片标识，重复请求必须字节一致。没有一次拼接整段视频的内存缓冲。
- 收到最后一块后释放采集资源，再异步上传和转换；本地助手从自己的 `media` 目录取 FFmpeg/ffprobe，检查通过后只提交一条 MP4 草稿。A/B、实际源起止、成片时长和结束原因分别记录，录制路线记为 `tabCapture-to-canvas`。
- 只有助手确认存在素材条目才显示已保存，并清理浏览器暂存；缓存清理失败不能反过来把已经存在的 MP4 报为保存失败。上传或转码失败保留原始块，草稿页提供“重试保存 MP4”。
- 已收齐并记录实际结束范围的任务可以重试；浏览器在录制中被强制关闭而没有可靠结束范围时，仅保留已落盘数据并显示错误，目前不能承诺自动恢复为完整成片。

## 2026-10-23：保存后预览恢复修正
