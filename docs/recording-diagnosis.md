## 当前反馈回路

对明确持续运动的短自制源，使用 FFprobe 的实际解码帧时间检查相邻视频帧间隔和音频独自延续的尾段；再用 FFmpeg 解码为 96×54 灰度图，比较画面变化。相对上次变化画面的平均像素差达到 0.5 灰度级才计为变化，允许缓慢运动累积差异。两项检查均采用 0.25 秒容差。该检查针对既有“文件长约两秒，视频仅到半秒”的症状，不用它判断普通静态画面的内容质量。

```powershell
py tools/check_recording.py .spike-data/draft/spike-native-8208b9defbe844dc8274e216fb0c82a6/material.webm
```

本次实跑：原反例仍失败，16 帧，末视频时间 0.528 秒、末音频时间 1.889 秒。有效两秒对照通过，59 帧，末视频时间 2.047 秒，最长未变化段 0.134 秒。

另外使用旧坏片生成明确标记的补帧反例：`tpad=stop_mode=clone:stop_duration=1.4,fps=30`，截为 1.95 秒并编码为 H.264/AAC。它只用于验证检查器，不是候选修复或新的浏览器录像。原时间戳检查会通过；补上画面检查后失败，识别到 1.366667 秒未变化段。不能仅把坏片转码或补齐时间戳作为录制通过。

## 0.0.5 诊断构建

保持原 Canvas 裁剪与定时绘制路线，另提供手动启用的观测：绘制次数/错误、输入解码与丢帧、输入时间、呈现回调，最多保留 64 个采样点。仅在精确的自制 fixture 页面、且使用隔离 `native-scratch` 保存模式时，允许同时录制原始标签流作为对照。两路结果单独保存并标记，平台视频不启用原始流对照。

实际 Edge 已报告构建 0.0.5，真实注册快捷键为 Ctrl+Shift+9；启用诊断本身不开始录制。网页自动化发送快捷键未触发扩展命令，不能算真实录制。浏览器控制连接一度中断后重新接通，诊断设置仍在；重载自制页面后重新设置 A=2、B=4，并保留页面等待用户真实快捷键。当前未产生新的双路媒体证据。

12 项诊断计数、录制器生命周期及裁剪几何检查通过，属于模拟环境检查，不能代替真实编解码。双编码器与呈现观测本身可能影响时序，诊断版偶然通过也不能证明旧问题修复。后续需比较两路实际媒体、冷启动与提前停止，再验证去掉诊断后的候选修复。记录见 [本轮诊断证据](evidence/recording-diagnosis-2026-10-21.json)。
