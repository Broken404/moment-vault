# Moment Vault 首版定稿总审

日期：2026-10-20。状态：用户明确“接受，可以定稿，开始落地吧”，整体方案已批准，进入正式开发；备用仅限迫不得已时临时选择。本文是批准时的使用与验收基线，不代表工程已完成。

完整规格以 [首版产品与技术方案](formal-plan.md) 为准，逐项设计依据见 [视觉与交互设计记录](visual-and-interaction-design.md)。本页用于把既有决定串成一次完整使用流程，不代表真实文件与三站集成已经验收。

## 1 一次完整使用

| 步骤 | 用户操作 | 产品结果 |
| --- | --- | --- |
| 安装与首次配置 | 安装本地助手、加载 Edge 扩展，分别选择草稿箱与资产库 | 检查助手、目录与实际快捷键；完成后回到普通网页使用桌宠 |
| 收集图片 | 直接拖图片到桌宠，或打开接收区域粘贴、拖入、选图 | 收到后冒小爱心，自动保存；一次批量输入为一条素材，原图分别保留 |
| 收集视频 | 在 B站、YouTube、X 打开录制模式，在原进度条选 A/B，需要时展开精调，在独立窗预览 | 快捷键从 A 开始录制，到 B 自动结束，也能提前结束；只保存实际录到的部分 |
| 继续观看 | 随时关闭录制模式 | 停止预览或正在进行的采集，恢复原观看状态；已录内容继续处理，完成后不重新弹窗 |
| 整理草稿 | 打开素材管理，查看本地文件、改名、补来源和备注，需要时合并多条 | 多个图片、视频可混合归成一条，各个原文件和对应说明保留；说明修改点击保存 |
| 人工入库 | 勾选草稿，点击入库 | 完整素材文件夹移入资产库；未选的留在草稿箱；跨盘先复制校验再清理源 |
| 后续管理 | 从资产库打开素材；不要的草稿放回收区 | 已入库素材可以删除，删除前只提醒一次不可恢复；草稿回收区可恢复且不自动清空 |
| 调整设置 | 在同一管理标签页切到设置，修改外观或操作偏好 | 外观立即生效、自动保存；输入项有效后保存，目录检查可用后切换，旧素材留原地 |

混合素材的完整示例：批量接收两张图片形成一条草稿，再录一段视频形成另一条；在草稿箱勾选两条合并，补共同说明后入库。最终一个素材文件夹中保留两张原图、一个实际视频和描述.md，不拼图、不拼接视频，不自动进入 AI 工作流。

正常录完或使用录制快捷键提前结束，保存成功后恢复独立预览窗与原 A/B，便于继续收集；用户主动关闭则优先退出。下一次录制必须由用户再次主动开始。

## 2 已确认的体验基线

- 入口为 P3-C 像素圆团，四宫格功能集中在身边；整体页面采用灵感画板的暖纸色、深灰与黄色强调。
- 默认跟随系统明暗，支持固定浅色或深色；桌宠默认中号 64 px，另有 48 / 80 px，默认不透明度 100%，可在 30%–100% 调节，面板不随桌宠变淡。
- 桌宠安静陪伴，不追鼠标。选段时双眼微收拢，管理时短暂扫视，设置时黄色角点短亮；收到图片冒爱心，不做嘴型或吃图片。
- 菜单与面板采用已通过的短促过渡；真实录制开始后收起选段界面，用画面外的小状态条显示时长、提前结束和关闭入口。
- 预览定位优先保持操作流畅，松手后显示最终边界的实际画面；未就绪时明确提示，旧画面不能冒充新位置。
- 设置与素材管理复用同一个管理标签页；普通网页入口可拖动、记位置、隐藏和恢复，播放器全屏时临时隐藏。
- 所有素材先进入草稿箱，成功提示依据实际保存结果。错误保留可恢复内容并提供重试，不以动画表示文件已保存。

## 3 技术选择与原因

| 部分 | 选择 | 为什么这样选 |
| --- | --- | --- |
| 网页入口与操作 | Edge Manifest V3 扩展 | 功能就在浏览器里使用，沿用已验证的扩展采集路线 |
| 界面 | TypeScript、React、Vite | 常见工具，共用表单、列表和状态，后续维护容易定位 |
| Windows 文件操作 | C#、.NET 10 LTS 本地助手 | 用微软生态处理目录和文件，选长期支持版本；不用用户手动启动服务 |
| 扩展与助手连接 | Native Messaging | 由浏览器连接本地助手，减少额外服务和端口管理 |
| 录制成片 | FFmpeg，MP4 / H.264 / AAC | 用成熟工具处理编码与封装；新增录制统一格式，导入文件保留原格式 |
| 数据保存 | 普通文件夹、媒体与 Markdown | 直接打开、复制、备份，首版不增加数据库或云端服务 |
| 自用安装 | Inno Setup、自包含助手、扩展构建目录 | 助手携带运行环境，扩展手动加载一次，日常无需终端或 Python |

.NET 10 当前属于长期支持版本，依据 [微软支持政策](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core)。原创代码的 MIT 许可随整体总审确认，仓库已添加 LICENSE，允许使用、修改与分发并要求保留许可和版权声明，依据 [MIT 许可原文](https://opensource.org/license/mit)；FFmpeg 等组件按各自构建与许可证处理，依据 [FFmpeg 许可说明](https://ffmpeg.org/legal.html)。当前没有进行软件公开分发。

## 4 实施时必须拿到的真实结果

1. 优先解决已有的快捷键提前结束短片停帧反例，以实际媒体连续性和音画检查确认修复。
2. 逐站落实原进度条 A/B、隐藏与重建后的恢复、独立预览、缓存与最新定位请求的配合，验证长视频中的短选区和弱网；备用方式不抵原进度条验收，不能用界面顺滑代替媒体检查。
3. 实现正式助手安装、系统目录选择、配置持久保存与 MP4 成片，确认重启后仍能继续使用。
4. 用真实文件跑通单张、批量、混合合并、说明保存、同盘与跨盘入库、回收恢复和永久删除。
5. 最后按本页完整路径回归安装、使用与重启，形成自用安装包、操作说明、实际支持范围与已知限制。

目前已经有三站普通视频和本地文件操作的试验证据；原进度条集成、独立预览缓存、正式助手与安装包仍是工程验收项。方案批准表示允许按这些目标开发，不表示它们已经完成。

## 5 原进度条是首版要求，备用只在恢复失败后临时选择

用户明确要求“想想办法，备用形式是迫不得已才使用的”。据此撤回此前自动展开精调区的提议；正常交付必须在三站目标页面的原进度条上操作 A/B。独立预览窗与日常精调的已确认设计保持作为实施依据。

工程选择是“三站各自认播放器，共用同一套选段逻辑”。2026-10-20 现场样本中，B站、YouTube 和 X 均能找到原轨道；其中 X 的控件需要交互后出现，且名为 slider 的节点只是播放头。这类隐藏、延迟生成和节点误认需要适配处理，不能作为立即使用备用方式的理由。观察依据与局限见 [现场记录](evidence/native-timeline-dom-2026-10-20.json)，官方能力及技术设计见 [适配研究](native-timeline-research.md)。本次仅完成结构检查，没有完成 Edge 扩展的原轨道集成。

实施先识别当前视频与真正的完整轨道，再在原位置叠加 A/B；页面滚动、影院布局、控件隐藏或重建时优先重算、恢复显示与重新绑定。同视频保留选区，切视频则清除旧绑定。只做站点限定的识别和事件驱动恢复，避免无限重试影响观看；网站改版主要修对应适配器。

上述路径失败且视频仍可回看时，才说明实际原因，提供“重新连接”和由用户选择的“临时使用精调”，不自动切换。视频本身无法定位时不能用精调承诺可用。三站原轨道的拖动、键盘、预览和录制联动仍必须分别实测通过；备用通过不算主体验完成。

以上规则已汇入主方案并随整体方案获准实施。直播、文字摘录、搜索分类、资产调用、AI、账号与云同步继续留在本轮范围之外；目录容量统计未进入已通过的设置设计，本轮不增加该功能。
