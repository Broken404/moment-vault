# 录制的本地 MP4 处理

2026-10-22 的本地处理模块已实现并用实际文件验证；2026-10-23 已接入正式录制代码链路并部署开发助手，真实首轮触发发现的布局错误已修正，修正版采集验收待完成。原停帧仍未定位。本模块通过不代表三站录制或安装包交付通过；后续状态见 [录制联动](recording-integration.md)。

## 文件与状态

1. `recordings.begin` 创建隐藏的录制上传，保存 A/B 和一个 WebM 附件标识。复用现有有序分块、确认与完整性校验，原文件不提前出现在草稿列表。
2. 停止并收齐最终块后，`recordings.process` 记录实际源区间和结束原因，启动助手拥有的 FFmpeg 子进程后立即返回 `processing`。后台使用 `recordings.status` 轮询；长转码不占用一条长时间未返回的 Native Messaging 请求。
3. 子进程输出唯一候选文件，固定为 MP4、H.264、AAC、30 fps 目标、质量预设 CRF 20 / fast。只向下调整奇数尺寸到可编码的偶数尺寸，不放大画面。检查实际解码、编码、尺寸和音视频轨道时长后，才复用原有完整性提交，将 MP4 和 `描述.md` 放入可见草稿文件夹。
4. 写入说明的 A/B、实际源区间、实际成片时长与结束原因分别保存，不把选区时长直接冒充成片时长。普通导入视频继续保留原格式和原字节，只有录制上传走转码。

转换任务只拥有自己的候选输出，协议线程更新上传和素材元数据。处理中阻止改变目录和重新组装输入；错误响应释放上传状态也不能绕过进行中的转换锁。已保存请求重试返回同一条素材。

## 失败与恢复

缺少组件、转码/检查失败或助手退出时，原始 WebM 和分块保留在 `.moment-vault/pending`，不显示“已保存”。助手正常退出会取消其视频子进程。重启后能识别被中断的处理，显式重试沿用原上传标识和原片；不会新增一条重复素材。失败的本次候选输出会尽量清理，原片不参与该清理；提交完成后才清理上传管理区。

此次同时修正了初始备注经过上传日志时丢失的问题：`Material.Note` 不进入素材头部 JSON，所以上传日志单独保存备注，并在读取时还原。已通过“带初始备注分块上传后提交”检查；没有修改用户已保存素材，也无法凭此恢复旧日志中原本未写入的备注。

产品助手只从自身目录的 `media/ffmpeg.exe`、`media/ffprobe.exe` 选取处理工具，浏览器消息不能传入可执行文件、系统命令或任意媒体路径。调用使用参数列表，不经过 shell。当前本机开发目录已暂存配套组件、原许可证/README 和版本哈希，最终分发材料及安装包尚未完成；缺少配套工具时返回真实的缺失状态，不静默使用系统 PATH。开发测试允许显式选择当前已安装的工具，不等同于产品分发。

## 已执行验证

本机 FFmpeg 8.1.1；实际既有两秒 Edge 自制录像与旧停帧文件各作为一个输入，6 项真实文件/编解码检查通过：分块与提交、幂等请求、缺组件后重启重试、旧反例拒绝发布、静止竖屏、处理中断后恢复、导入保留原格式。其中前两类检查合为一个完整流程用例。

实际正常录像产出 964×542、H.264/AAC、30 fps、2.1 秒 MP4。独立解码检查得到 63 帧，末视频时间 2.066667 秒、末音频时间 2.057 秒、最长未变化画面 0.066667 秒；抽帧实看源时钟从 2.000 秒推进到 3.967 秒。静止竖屏输出 180×320、2 秒，说明没有将普通静止画面错误地按运动夹具判为失败。

旧坏片被轨道时长检查阻止提交，原片哈希保持不变。这只新增了对该症状的保存检查，不能修复丢失的源画面，也不能检测所有已重复补齐帧的停帧。原捕捉问题仍需冷启动、重复采集、去诊断等真实验证。

可移植重跑不依赖保留的录像，直接生成运动片和“0.5 秒视频 / 2 秒声音”的合成反例：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/check-recording-media.ps1
```

该命令要求开发环境已安装 .NET 10 与 FFmpeg，在被忽略的 `.local-data` 生成独立夹具和结果，6 项均已实际通过；合成反例不会冒充真实浏览器失败。Native Messaging 长度前缀和操作分派在进程内走实际代码，FFmpeg 为真实子进程；这仍不是 Edge 到新处理模块的端到端验收。另有 15 项原生文件/协议检查和完整前端检查通过。结构化结果见 [处理模块证据](evidence/recording-processing-2026-10-22.json)。

实现依据：[FFmpeg 转码与选流文档](https://ffmpeg.org/ffmpeg.html)、[.NET 参数列表](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.processstartinfo.argumentlist?view=net-10.0)。
