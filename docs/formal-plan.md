## 2 安装后如何开始使用

首次使用依次完成：安装 Windows 本地助手 → 在 Edge 加载扩展 → 检查助手连接与录制快捷键 → 分别选择草稿箱和资产库。

首个自用版本交付助手安装包和扩展构建目录。助手由安装包注册，扩展按安装说明手动加载一次。日常使用无需打开终端、启动本地网页服务或安装 Python。商店上架另属公开分发阶段，不阻塞本轮自用版本交付。

扩展安装后打开自己的设置页完成初始化；已有网页可刷新后显示悬浮球。两个目录未配置或不可访问时，点击采集、整理或入库入口会说明原因，并提供“去设置”。

首次配置页面的布局与提示已通过预览：一页内分别选择草稿箱与资产库，显示用途、路径及选择状态，下方显示本地助手连接与实际录制快捷键，其他设置先用默认值。目录未选齐、助手连接中断或目录不可用时禁用“完成配置”并说明原因；连接中断可重新检测、查看安装说明，目录不可用保留路径并允许重新选择。正常完成后提示返回普通网页使用桌宠。设计通过不代表真实目录选择和配置保存已实现。

悬浮入口在已获站点权限的普通 HTTP、HTTPS 网页显示。视觉采用已选择的“灵感画板”气质，入口为已确认的 P3-C 像素圆团；角色旁展开同风格四宫格菜单，再次点击收起。造型、布局、深浅色、主要功能界面与组合动效已通过预览：

| 入口 | 操作 |
| --- | --- |
| 屏幕录制 | 进入当前目标视频的选段模式；其他网站置灰并说明支持范围 |
| 设置 | 在与素材管理共用的管理标签页直接进入设置，配置目录、语言、时间步长、快捷键和悬浮球外观 |
| 接收截图 | 打开并聚焦图片接收区域，可立即粘贴或拖入 |
| 素材管理 | 在独立浏览器标签页打开，默认进入草稿箱，提供本地目录打开、整理、审核入库及基本删除 |

浏览器内部页、扩展管理页及浏览器禁止注入的页面不显示网页入口。设置也可从扩展工具栏进入。

设置与素材管理共用一个独立于来源网页的管理标签页，左侧增加“设置”入口；已有管理页时直接复用并切换到对应位置。点击“素材管理”进入草稿箱，点击“设置”直接进入设置；不要求用户为两个功能分别管理浏览器标签页。完整设置已确认一页分组展示，依次为存储位置、界面与桌宠、视频与快捷键、本地助手，内容直接展开，底部放恢复默认设置；完整页面的视觉、控件与操作反馈已通过预览。

## 3 图片和视频如何采集

### 3.1 图片接收

打开“接收截图”后，接收区域自动获得焦点。粘贴或拖入即开始保存，不要求再点一次保存；完成后在原区域显示缩略图与“已存入草稿箱”，多图显示图片数量。

也支持已确认的直接收图：把图片拖到 P3-C 桌宠本体，即自动保存到草稿箱，无须先开菜单或面板；沿用相同目录检查和一批图片归为一条素材的规则。收到有效图片后，桌宠周围冒出一簇小爱心；已取消吃图片、张嘴与咀嚼动画。爱心表示接收确认，保存中、成功与失败按实际写入结果另行反馈；动作不阻塞保存，也不将整个网页变成拖放接收区。

单次操作接收到的多张图片属于同一条素材，分别保留原图，不拼成一张图片。连续的独立粘贴操作先各自成条，需要时再到草稿列表合并。图片接收不依赖视频选段模式。

来源和备注可稍后补充。外部截图不自动绑定当前网页；当前页只作为来源候选，未经确认不当作真实出处。导入时间与截图实际发生时间分开，未知的信息留空。

实施默认支持 PNG、JPEG、WebP、GIF 文件，GIF 保留原文件，缩略预览可用首帧。纯文本或图片链接不直接冒充图片文件；输入不可接收时说明原因。接收失败保留当前输入和预览，提供重试。

素材管理提供本地文件导入，接收图片及 MP4、WebM、MOV 视频文件。一次选入多个文件按一条素材保存；导入的视频保留原文件和实际格式，新增录制的视频按第 3.3 节生成 MP4。

### 3.2 视频选段

在 B站、YouTube、X 的目标视频上打开选段模式，在原播放器已有的进度条上叠加可拖动起点 A、终点 B 和选区高亮；这项是首版验收要求，不能用技术试验的独立滑条或备用方式代替完成。多个播放器存在时，先选择目标；选段期间锁定该视频的身份。三站原进度条适配尚未实现或验收。

技术采用“三站各自识别播放器，共用一套选段逻辑”：分别识别真实轨道并核对所属视频、几何和时间范围，在原轨道位置叠加自有标记。控件隐藏、延迟出现、滚动缩放或播放器重建时先恢复显示、重新定位或绑定，不因一次查找失败自动降级；同视频保留 A/B，切源不沿用旧状态。只有这些恢复确实失败、媒体本身仍可定位时，才提供“重新连接”与用户自行选择的“临时使用精调”。普通精调仍是长视频的精确调整工具，备用通过不算原进度条验收通过。具体恢复规则见 [视频选段](video-range-selection.md)，三站样本结构观察见 [现场记录](evidence/native-timeline-dom-2026-10-20.json)；现场记录并非正式 Edge 扩展验收。

录制模式默认关闭，用户需要时主动调用，也能随时退出。模式开启后，桌宠菜单中的对应入口提供退出操作，独立预览窗和录制小状态条均保留明确的关闭入口。关闭后移除预览窗、A/B 标记和选区高亮，停止预览定位与快捷键接管，恢复普通观看；不能只把窗口藏起来却继续控制播放器。

已确认提供独立、可自定义的“打开／关闭录制模式”快捷键，与“开始／提前结束录制”分开。模式关闭时按下只进入选段，不自动录制；模式开启时按下沿用关闭按钮的退出、停止采集、保存已录内容及观看恢复规则。连续重复事件不得造成界面反复开关。

进入时保存观看位置、播放或暂停状态及临时调整的播放设置，然后暂停原视频。关闭模式后恢复原观看位置和播放状态。平台切换到另一个视频后，不将旧时间强行应用到新视频。快速反复开关时，已退出会话的异步定位或保存回调不得重新展开界面或改变当前观看位置。

选段时显示 A/B 时间与选区时长，原进度条承担主要的全片定位与选段。用户已明确保留独立的网页内预览窗，用于边界画面与整段试播，可拖动及调整大小，不改为在原视频画面中预览。“预览选区”从 A 播放到 B，不产生素材。独立窗中的“精细调整”已确认为首版功能，默认收起，展开后放大当前端点附近的范围，便于长视频中的短选区或靠近的 A/B 标记调整；原进度条与精调共用同一组选区并同步。

整合界面的布局和操作已通过预览：原进度条 A/B 标记上下错开，独立窗依次显示边界画面与定位状态、可切换的 A/B 时间卡片、选区时长、预览选区、精细调整和快捷键提示。精调从当前端点附近 20 秒开始，可放大缩小、局部拖动或直接输入时间；缩放按预览的 2–120 秒作为实施取值，不改变选区。无效时间或越过另一端点时提示并保留有效值。预览窗参考宽度改为当前通过版本的 330 px，实际适应视口并可调整，不沿用早期 480 px 为当前默认参考。

用户强调缓存与卡顿是关键体验。技术路线优先验证复用源播放器已加载内容与帧输出，在独立窗显示并暂存少量近期预览帧；不假设再建一个播放器就能共享网站缓存。标记与时间读数及时更新，媒体定位合并请求，只追赶最新目标；未缓存时如实显示正在加载，不用旧画面冒充新边界。缓存有容量限制，切源或相关画面参数变化时失效，退出选段释放。用户已接受拖动期间优先流畅预览、松手后针对最终边界完成准确定位；画面未就绪时继续提示，不能用邻近缓存帧冒充最终结果。三站的实际缓存复用与响应性能仍需专项验证，详见 [视频选段](video-range-selection.md)。

默认方向键调整当前选中端点 5 秒，Ctrl＋方向键调整 1 秒，两项均可在设置中修改。备注输入框保留正常键盘操作。端点满足 A＜B，位于当前可回看范围内；越界停止移动，不交换两个端点。

初始选区从当前观看位置向后取 5 秒，尾部不足时取剩余部分；已在结尾时取最后最多 5 秒。局部精调默认收起，展开时显示当前端点附近 20 秒，保留缩放；早期附近 30 秒的建议被已通过的预览取代。选区不另设业务时长上限，实际受可回看范围、磁盘空间及有效媒体产出约束。

播放器全屏时，先回到网页模式完成选段与录制。默认完整预览播放一次，保留源视频声音，不增加循环录制。

### 3.3 主动录制与文件保存

有效选区设置后，用户按录制快捷键，从 A 回放并录制，到 B 自动结束。再次按同一个快捷键提前结束，保存实际录到的部分。长按、重复按键不会连续创建或误停多条任务；同一时刻只录制一个目标视频。

状态依次为“准备录制 → 录制中 → 正在处理并保存 → 已存入草稿箱”，失败单独显示。用户已确认真实录制开始后收起完整选段界面，改为视频画面外的小状态条，显示录制中、已录时长及提前结束快捷键，锁定 A/B。选段标记、悬浮球及状态控件避开被捕捉区域。

到 B 正常结束或按录制快捷键提前结束后，实际保存成功再恢复独立预览窗，保留刚才的 A/B，并提示“已存入草稿箱”，方便继续调整、收集下一段；不会自动开始下一次录制。用户随后关闭模式时，再恢复进入前的观看位置和播放状态。

随时关闭优先于上述恢复规则：准备阶段关闭则取消未开始的采集；录制中关闭则停止采集并保存实际录到的部分，待采集已停止即可恢复观看，不要求等待转码和文件写入完成。选段、预览或处理保存阶段关闭均立即收起操作界面。关闭不取消已开始的必要文件保存，保存结果以不遮挡视频的轻提示反馈；保存失败仍保留可恢复内容及重试入口。已关闭的模式不因保存成功或失败自动重新展开。

录制期间保持当前标签和目标视频完整可见。切换来源、离开标签、视频不可继续播放或几何位置变化导致无法可靠采集时，停止本次采集，保留有效片段并说明中断原因；中断片段不宣称覆盖完整选区。

新增录制的成片统一为 MP4，采用 H.264 视频和 AAC 音频。画面保持实际捕捉的比例和尺寸，不额外放大低清画面；捕捉目标为 30 fps，实际画面变化受源视频影响。默认采用质量优先的固定编码预设，首版不增加编码参数设置页。

浏览器中间文件由助手调用 FFmpeg 转换并补齐封装信息。转换与最终写入成功后才显示已保存；失败保留可恢复的中间文件并允许重试。原选区、实际源视频区间、成片时长及结束原因分别记录。

### 3.4 三个平台的实施覆盖

| 平台 | 首版目标页面与情境 |
| --- | --- |
| B站 | 普通视频、分P与分集切换后的可回看视频，正确关联当前内容 |
| YouTube | 常规视频与 Shorts，处理站内跳转、正文切换和目标身份变化 |
| X | 帖子详情及信息流中的可回看视频，多视频时明确选中目标帖子和媒体 |

这些是实施与验收目标。现有证据只覆盖三个平台的普通视频样本，新增页面形式通过实测后才列为发布支持项。直播不在首版范围，其他网页中的跨源嵌入式播放器不作为本版目标页面。

## 4 素材文件夹和草稿整理

### 4.1 一条素材的含义

素材是一次整理和人工审核的单位，可以包含一个或多个附件。附件数量不等于素材条数。

    草稿箱/
    └── 20261020-素材组-001/
        ├── 图片-001.png
        ├── 图片-002.jpg
        ├── 视频-001.mp4
        └── 描述.md

草稿与资产库使用相同结构。媒体与描述从采集阶段共同保存，入库、合并和回收都保持关联。

有可靠来源时，单条素材按“日期＋平台＋来源标题”自动命名；没有标题时使用类型和编号。多图可使用“日期＋图片组＋编号”，混合归组使用“日期＋素材组＋编号”。保存时不要求用户起名；草稿列表可改名，并同步文件夹名称。同名自动补编号，不覆盖已有内容。

### 4.2 草稿列表

素材管理在独立的浏览器标签页打开，默认显示草稿列表，显示缩略图、名称、收集时间及附件数量，支持多选。页面布局与风格已通过预览：左侧切换草稿箱、资产库和回收区，中间勾选整理，右侧查看当前条目并编辑草稿名称与说明；批量操作集中在列表上方，未选择时禁用。多文件素材完整查看时打开条目文件夹；单文件素材可调用系统默认软件打开。

每条草稿提供改名和“编辑说明”。用户可补充或修正来源、填写自由备注，点击“保存”后更新对应的描述.md。来源和备注可以留空，不影响入库。

已通过的页面将上述编辑放在右侧说明区，使用“保存修改”提交；多附件分别保留来源与附件备注，整组备注单独显示，资产库中的说明只读。窄窗口重新排列导航、列表与说明区，保持可操作。

多文件素材保留每个附件自己的来源、原收集时间、视频区间及备注，并提供整条素材的共同备注。统一备注不静默覆盖所有成员的来源。

### 4.3 合并为一条

在草稿列表中勾选多条素材，点击“合并为一条”。支持多图、多视频及图片与视频混合；合并采用归组方式，各个媒体文件分别保留，不做图片拼接或视频剪接。

合并后生成一条草稿，保留各附件的身份、来源、时间和备注，原条目由新条目替代。原有整体备注分项保留，用户可再编辑共同说明。合并不自动入库；目标内容完整保存后才清理原条目。

附件在描述中保留稳定顺序。批量导入记录收到的文件顺序，合并按操作时列表中显示的条目顺序归组，各条内部顺序保留；文件重名时补编号并同步对应关系。

## 5 审核入库和基本删除

草稿列表勾选素材后点击“入库”，即表达本次人工审核决定。插件将完整素材文件夹移入当前资产库，反馈实际完成数量，不增加重复的审核确认弹窗。未勾选的素材继续保留。

入库支持不同磁盘：先完整复制和校验，再清理草稿源数据。部分完成时列出实际结果和未完成条目，重试处理未完成部分。同名补编号，不能覆盖其他素材。

已入库素材不提供撤回草稿箱或撤销入库。素材管理的资产库视图沿用轻量列表，仅提供本地打开和删除，不增加检索或分类功能。点击删除后提示“删除后不可恢复”，确认一次后永久删除整条素材及全部附件。

草稿里明确不要的条目可移到应用内回收区，支持恢复回所属草稿箱，第一版不自动清空。回收区随原草稿箱保存，切换目录不搬迁它；主动永久删除回收内容时同样提示不可恢复并确认一次。

## 7 技术方案及选择理由

采用“Edge 扩展＋Windows 本地助手”，两部分通过 Native Messaging 通信。扩展负责网页内操作和录制，助手负责本地文件及系统窗口；不运行常驻网页服务器，不增加云端后端。

| 部分 | 选择 | 用容易理解的话解释 |
| --- | --- | --- |
| 扩展 | Manifest V3 | 使用 Edge 正式支持的扩展方式，与已验证路线一致 |
| 界面 | TypeScript、React、Vite | 用常见前端工具共用表单、列表和状态，后续加改功能时容易定位 |
| 本地助手 | C#、.NET 10 LTS | 使用微软的 Windows 开发生态处理目录、文件和系统操作，采用长期支持版本 |
| 通信 | Edge Native Messaging | Edge 按需启动并连接助手，用户日常不用手动开服务 |
| 成片处理 | FFmpeg 独立进程 | 复用现成媒体工具完成编码、封装与检查，避免自行编写视频处理器 |
| 数据 | 普通文件夹、媒体、Markdown | 用户可直接查看、复制和备份，首版不引入数据库服务 |
| 安装包 | Inno Setup、.NET 自包含发布 | 助手和运行环境一起分发，用户不需要先安装开发环境或 .NET |

Native Messaging 的启动与安装方式见 [Edge 官方文档](https://learn.microsoft.com/en-us/microsoft-edge/extensions/developer-guide/native-messaging)。.NET 10 的支持期见 [.NET 支持政策](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core)，自包含分发见 [.NET 发布说明](https://learn.microsoft.com/en-us/dotnet/core/deploying/)。界面基础见 [React TypeScript](https://react.dev/learn/typescript) 和 [Vite](https://vite.dev/guide/)，安装工具见 [Inno Setup](https://jrsoftware.org/isinfo.php)，媒体处理见 [FFmpeg](https://ffmpeg.org/ffmpeg.html)。

### 7.2 录制和文件操作

离屏页负责媒体录制，后台与助手转发分块数据；助手逐块落到临时文件，避免整段视频经一次巨型消息传输。每个请求带独立编号，录制块带顺序和确认，停止后收齐最终块再处理成片。

媒体操作采用“临时写入 → 完整性检查 → 提交为正式条目”。合并、跨盘入库在目标完整后才清理源数据；记录操作进度，重启后能识别未完成操作。中间文件和事务记录不作为已完成素材显示。

素材列表从当前配置目录读取，目录位置表达当前状态。浏览器存储只保存操作偏好、目录引用和临时会话信息；素材身份不依赖浏览器缓存。

### 7.3 描述与附件数据

每条素材及每个附件都有独立稳定 ID，与可修改的文件夹名称分开。描述.md 使用 UTF-8，顶部为软件可读的 YAML 固定字段，下方为自由备注；不另维护一份内容相互竞争的描述数据库。

| 数据 | 记录内容 |
| --- | --- |
| 素材 | 数据格式版本、稳定 ID、名称、创建时间、附件顺序、人工入库记录 |
| 每个附件 | 稳定 ID、相对文件名、实际类型、大小、校验值、原收集时间、可确认的来源与备注 |
| 视频附件 | 源视频身份、原选区、实际源区间、成片时长、采集方式和结束原因 |
| 合并记录 | 原条目 ID 与原有说明的对应关系，原附件身份和时间保持 |
| 自由备注 | 用户直接编辑的文字，合并时分项保留旧说明 |

日期时间记录明确时区，视频位置与导入时间分开。未知来源留空，外部图片不自动获得当前网页的真实来源身份。

普通文本编辑器仍可修改描述。软件保存前检查文件是否被外部更新，保留未识别的附加字段；格式有误时提示修复，媒体仍可从本地查看，不覆盖无法解析的说明。

### 7.4 安装和数据边界

助手以当前用户安装，注册固定扩展 ID 对应的 Native Messaging 宿主。升级保持安装路径与通信身份稳定，扩展检查协议版本；卸载程序保留用户素材目录。

正式助手只提供项目需要的操作，按已选根目录和条目 ID 定位素材；不接收任意系统命令。草稿箱与资产库必须互不包含，保留的管理目录不当作素材条目。

用户的媒体、来源、浏览器配置和运行日志不进入代码仓库。本版不上传素材，不收集遥测，不要求配置模型或密钥。

发行包固定依赖版本，附构建说明、校验信息和第三方许可证；随包提供的 FFmpeg 采用明确可分发的构建，并保留对应来源与许可信息，见 [FFmpeg 许可说明](https://ffmpeg.org/legal.html)。

原创代码随整体评审确认采用 MIT，仓库已添加 LICENSE：允许他人使用、修改、分发和商用，要求保留相应许可与版权声明，见 [MIT 许可原文](https://opensource.org/license/mit)。第三方组件继续使用各自许可。首次交付沿用现有名称 Moment Vault；当前不进行商店提交或软件公开发布。
